## 1. 目标与页面分工

购物车只帮助客户完成三件事：选择要购买的服务、调整数量、去结算。减少重复阅读和输入，不增加必须完成的操作。

| 页面 | 用户在这里完成什么 |
| --- | --- |
| 服务详情 | 了解服务说明、须知及价格，加入购物车或立即下单 |
| 购物车 | 勾选服务、调整数量、移除服务、核对已选合计并去结算 |
| 确认订单 | 确认地址、选择期望上门时间，按需填写备注，提交订单 |
| 订单详情 | 查看订单进度，并在允许的状态下更新备注或补充资料 |

服务名称、数量和价格是购物车及结算页都需要核对的关键信息，保留必要摘要；详细说明和选填表单不在购物车重复出现。

## 3. 目标布局与视觉

```text
原生导航：购物车

┌───────────────────────────────┐
│ ○  [服务图]  水管漏水检测         │
│              ¥10.00/次   [− 1 +]│
└───────────────────────────────┘
┌───────────────────────────────┐
│ ✓  [服务图]  另一项服务           │
│              ¥单价/单位  [− 2 +]│
└───────────────────────────────┘

固定底栏：✓ 全选    合计 ¥0.00    [去结算(1)]
```

- 沿用深蓝主题、白色服务卡和浅灰页面背景；页面左右间距 16px、卡片间距约 10–12px、内边距约 12px，圆角使用公共变量。
- 单项左侧勾选控件和 56×56px 图片，右侧为名称及“单价／数量”行；不再分成卡片头、卡片体和卡片尾。
- 名称 14–15px、最多两行；单价及单位 12–13px；底栏合计金额突出，其他文字保持辅助层级。
- 数量控件沿用共享的紧凑尺寸，视觉高度 32px；数量区要能容纳四位整数，不能被价格挤压。
- 图片或名称可点击查看服务详情，不增加额外文字入口；返回购物车保留选中状态。
- 勾选圆圈视觉保持小巧，但勾选、全选的实际触摸区域至少 44×44px；全选文字及图标属于同一个完整点击区域。
- 普通单行名称的服务卡目标高度约 84–100px；长名称、长单位及系统大字体允许自然增高，不靠固定高度裁切内容。
- 320px、375px、430px 宽度下，价格与数量不重叠；必要时价格单独换行，不隐藏金额或压缩点击区域。
- 固定底栏沿用安全区处理与明确层级，不能被滑动服务行、其他透明容器或原生媒体组件遮挡；内容只预留实际底栏和适量间距。

## 4. 交互规则

### 4.1 勾选与合计

- 首次进入默认勾选可购买服务；用户手动选择后，在本次购物车操作、数量更新及页面往返中保留选择，以服务项稳定 ID 识别。
- 全选只作用于可购买项，点击可在全选／取消全选间切换；部分选中时点击全选选中全部可购买项。
- 底栏合计仅计算勾选且可购买的服务，金额以整数分运算、展示两位小数。
- “去结算(N)”中的 N 表示已选服务项数，不是数量之和。例如两项服务分别购买 2 次和 3 台，显示“去结算(2)”。
- 未选任何服务时合计为 ¥0.00，去结算按钮禁用；全选仍可点击恢复选择。全为不可购买项时不能结算。

### 4.2 调整数量

- 沿用 1–9999 的整数规则；减至 1 后禁用减号，不自动删除服务。
- 更新中限制重复数量请求，成功后更新数量、真实单价及已选合计；失败显示简短提示，恢复可操作状态，不误报已保存。
- 未选中的服务也可调整数量，其金额不计入当前合计。
- 刷新响应不得恢复已经取消的勾选，较旧响应不能覆盖后续结果；服务选择和操作均按稳定 ID 处理，不依赖会变化的行下标。

### 4.3 删除与查看详情

- 左滑显示红色“删除”，右滑收起；纵向滚动不误触左滑，滑动结束后不能误跳到详情。
- 长按服务行提供仅含“删除服务”的操作菜单，作为不熟悉左滑时的替代入口；单击仍是查看详情，不触发删除。
- 点击删除沿用一次确认，取消不改变数据；删除失败保留服务和选择，成功后重新计算全选、金额和已选数量。
- 删除最后一项后进入空态，隐藏底栏；空态保留“购物车还是空的”和一个“去选择服务”按钮。
- 图片加载失败显示中性占位，不影响勾选、数量、删除或结算。

### 4.4 异常服务

- 已下架项保留以便客户识别和删除，显示“已下架”，不可选、不可增减数量，不计入全选及合计。
- 服务内容或价格变化时，仅该项显示紧凑的“服务信息已更新”及必要的查看／确认操作，沿用现有版本校验，不自动接受新价格。
- 未确认更新时不能直接结算；提供明确原因及当前项入口，不显示大块说明、备注或资料表单。

### 4.5 去结算

- 仅传递当前勾选的服务项 ID，进入既有确认订单页，不在购物车要求先补充备注、上传资料、选择地址或预约时间。
- 跳转前重新核对所选项目的可用性及版本；服务被移除、下架或待确认时留在购物车并提示原因。
- 移除当前购物车结算流程中的逐项 `saveDemand` 调用：购物车不再编辑备注，不能让没有改动的选填内容保存成为去结算的前置网络请求。
- 购物车中原本保存的备注及资料仍通过购物车读取结果带入确认订单，不能因删除 UI 而写成空值、解除媒体关联或要求客户重新填写。
- 去结算过程中显示加载状态，防止重复跳转；保存以外的刷新、校验、写入跳转参数及导航异常均有统一恢复处理，失败后全选及去结算不能永久锁定。
- 返回购物车后可继续调整、选择和重试，不重新默认全选；确认订单仍保留已实现的加载重试、备注编辑及提交幂等逻辑。

## 5. 实施范围与数据边界

- 主要调整 `pages/cart/index.wxml`、`index.wxss`、`index.ts`、`index.json`，以及对应页面逻辑回归用例。
- 删除购物车不再使用的 `service-content` 注册、展开状态、备注输入／失焦保存、附件上传／移除及私有需求媒体加载代码；保留公共组件和接口，确认订单及订单详情仍需使用。
- 保留当前购物车读取、数量更新、删除和版本确认接口；不新增后端接口或数据库迁移，不清空购物车、订单或客户资料。
- 主图沿用公共图片 URL 处理，支持相对地址与完整地址；购物车进入或刷新时不再为隐藏的备注附件发起下载。
- 地址和预约仍只在确认订单处理；占位提示沿用“请选择期望上门时间”。备注统一称为“备注”，输入提示沿用“请描述现场情况或您的服务要求，帮助师傅判断问题”。
- 此次只精简购物车，不增加确认订单上的服务说明／须知，也不改变订单创建后的备注补充能力。
- “加入购物车仅加购、不自动结算”及“立即下单独立结算”继续有效。

## 6. 验收标准

1. 正常服务项只有勾选、图片、名称、单价／单位及数量；购物车无服务约定、说明／须知全文、备注表单、附件区、重复补充入口、卡片尾及列表结束文案。
2. 客户不填写任何备注、不上传资料即可勾选并进入确认订单；购物车跳转前不调用备注保存接口、不下载隐藏的需求附件。
3. 已有购物车备注和媒体关联不被清空，在确认订单打开“备注”能看到原有内容，并可继续编辑。
4. 全选、取消全选、单项选择、部分选择的金额与按钮数量正确；触摸勾选文字和图标都能操作，不被底部遮挡。
5. 数量边界、未选项调整、失败重试及刷新后的选择保留正确；无过期响应覆盖新状态。
6. 左右滑动、纵向滚动、长按删除、删除确认／取消／失败、详情往返互不误触；删至空购物车的状态正确。
7. 只结算勾选项，未勾选服务保留；下架／移除／待确认更新能被识别，不静默改价。
8. 刷新及导航失败、连续点击、页面往返后操作状态正确，不能再出现全选和去结算长时间点不动。
9. 在 320px、375px、430px 和大字体场景下核对卡片密度、长名称／单位、四位数量、较大金额、图片失败及底部安全区，无重叠、截断关键金额或大块无用留白。
10. 小程序类型检查、WXML／WXSS 编译及相关购物车、勾选结算逻辑回归通过；用开发者工具验证实际点击和滑动，真机未检查项如实记录。

## 1. 目标与核心决策

客户点击“手机号快捷登录”，通过微信原生手机号授权完成登录。手机号尚未注册时自动创建客户档案，已注册时进入该手机号对应的账户。客户无需填写密码或单独进行注册。所有客户私有数据由后端按照组织和客户归属进行隔离。

核心决策：

1. 第一阶段使用微信 `getPhoneNumber` 组件获取专用 `phoneCode`，后端调用微信 `phonenumber.getPhoneNumber` 兑换平台验证的手机号。
2. 同时使用 `wx.login` 获取独立的 `loginCode`，由后端通过 `code2Session` 获取 OpenID，用于记录本次登录的微信环境和校验会话。两个 Code 分别处理，不能混用。
3. 账户唯一依据为同一组织内的规范化登录手机号；业务数据继续使用稳定的内部 `customer_id` 关联。
4. 复用现有 `customer` 表，新增微信身份关联和客户会话记录。相同手机号在不同微信环境登录时进入同一个客户账户。
5. 客户使用独立的 Bearer Token，角色固定为 `CUSTOMER`。客户 ID、组织 ID 和角色由后端认证确定。
6. 服务目录允许游客浏览；访问个人数据和执行个人业务操作需要登录。
7. 头像、昵称是可选资料；登录手机号与订单联系电话分别处理，允许替家人下单。
8. 第一阶段完成手机号快捷登录、全部用户数据隔离、头像昵称编辑，以及后台平台注册用户管理和使用情况查询。
9. 小程序尚未上线，现有客户及关联业务数据上线前一次性清空；真实用户通过手机号快捷登录重新建档。
10. 后台“用户管理”管理小程序客户，与已有“后台用户”管理员账号模块分别展示；注册人数按客户账户去重统计。

本规格采用“手机号授权登录、未注册自动注册、登录注册合一”的产品交互。手机号兑换本身不依赖 `wx.login`；本项目额外校验 OpenID 是会话环境验证的设计决策，不是微信手机号 API 的前置要求。

- 请求、上传和下载封装已支持发送 Bearer Token。

- 管理员和师傅已有各自的数据库会话机制，可参考其随机 Token 和哈希存储实现。
- React 后台已有 `/customers`“客户资产”占位页、管理员账号管理、Casbin 菜单与操作权限，可接入小程序用户管理。

### 2.2 当前问题

- `apps/wechat-mini/miniprogram/app.ts` 在开发版启动时自动保存 `local-customer-1`。
- `apps/server-go/internal/platform/auth/auth.go` 将该 Token 固定映射为组织 1、客户 1。
- 客户认证仅有本地演示路径，没有手机号授权兑换、手机号唯一约束、微信环境关联和真实客户会话。
- 不同微信用户在开发环境下使用同一个客户身份，购物车、地址、订单等数据混用。
- `internal/fulfillment/parallel.go` 中 `SubmitRating` 只检查客户角色，缺少工单所属订单的客户归属校验。
- “我的”页面中的订单计数、订单已读状态等内存和本地缓存需要按客户隔离，并在身份变化时清理。

上述为已确认的基线，不代表所有接口已完成权限审计；实施时必须覆盖本规格列出的全部客户接口。

## 4. 身份与组织规则

### 4.1 手机号账户与微信环境

- 同一 `org_id` 下，一个规范化登录手机号只能对应一个客户，使用数据库唯一约束保证。
- 第一阶段支持中国大陆手机号：微信返回的国家区号为 `86`，`purePhoneNumber` 按 `^1\d{10}$` 校验，规范化为 `+86` 加 11 位号码。
- 超出本期号码范围返回明确的不支持提示，不截取、猜测或默默转换其他国家号码。
- 手机号由后端直接向微信兑换，不能接受前端提交的明文手机号作为登录凭证。
- 同一手机号重复授权、换设备、清理缓存或换微信环境后登录，仍进入同一个客户账户。
- 需要重新授权时，仅按本次微信兑换的手机号确定账户，不复用失效缓存中的客户 ID；不同手机号数据不自动合并，也不能把原账户手机号直接改写。有效登录态下不提供选择另一手机号登录的入口。
- 微信身份通过 `(appid, openid)` 识别环境，但不能单独作为客户账户的登录凭证或唯一归属依据。
- 一个客户可关联多个微信环境，一个微信环境也可能先后登录多个手机号账户；环境关联记录不具有独立登录权限。
- UnionID 可空，本期不用于账户合并。
- 首次注册由服务端生成随机昵称（“用户”加随机字符串，不使用手机号或微信标识），使用统一默认头像；再次登录保留已有昵称与头像。头像昵称变化不改变客户 ID。
- 登录手机号与订单联系电话相互独立。修改订单联系电话不修改登录账号，也不改变订单归属。
- 手机号快速验证不保证每次实时验号，不能宣传为每次完成实时短信验证。号码回收再分配无法仅靠手机号唯一约束识别；登录手机号变更、疑似号码归属争议和账户恢复须另行制定核验流程，不通过客户端编辑资料直接处理。

### 4.2 组织归属

- 第一阶段采用单组织入口，由服务端 `CUSTOMER_DEFAULT_ORG_ID` 确定所属组织，默认值为 1。
- 新客户、身份绑定、会话和业务数据的组织必须一致。
- 客户登录请求不接受 `orgId`、`customerId` 或 `role` 来选择身份。
- 后续多组织入口必须由服务端建立受控的入口映射；当前不得通过增加客户端组织参数开放跨组织登录。
- 客户账户按组织查找；微信环境关联必须属于当前组织的客户，不通过环境关联跨组织恢复账号。

### 4.3 账户状态

- 客户状态为 `ACTIVE` 或 `DISABLED`，新建客户默认 `ACTIVE`。
- 禁用或软删除的客户不能登录；已有会话在下一次请求时也必须失效。
- 被禁用或软删除客户的登录手机号继续占用唯一身份，不得通过另一微信环境或重新登录创建同手机号替代账户。
- 第一阶段不提供客户端自行修改账户状态的接口。

## 5. 登录与小程序交互

### 5.1 手机号快捷登录与自动注册

```text
游客浏览服务
→ 点击“手机号快捷登录”或进入个人业务
→ 点击微信原生手机号授权按钮（getPhoneNumber）
→ 尚未同意隐私时弹出隐私确认，用户阅读并点击“同意并继续”
→ 自动继续本次手机号授权；已同意隐私时直接进入手机号授权
→ 用户选择号码并同意，客户端获得 phoneCode
→ wx.login 获得独立 loginCode
→ POST /api/v1/mini/auth/phone/login
→ 后端兑换手机号并校验 code2Session 返回的微信环境
→ 按当前组织和规范化手机号查找客户
→ 未注册时事务创建客户；已注册时复用客户
→ 记录微信环境关联并签发客户会话 Token
→ 保存登录态并回到原页面
```

- 登录页展示“手机号快捷登录”，说明“未注册手机号将自动创建账号”，不设置独立注册表单。
- 登录页不设置协议复选框，也不设置独立的资料完善步骤。隐私确认弹窗提供协议链接、“暂不同意”和原生“同意并继续”按钮，通过 `onNeedPrivacyAuthorization` 的 pending/resolve 机制，在隐私同意后继续原手机号按钮的授权，不要求再次点击登录。已经同意的隐私指引不重复弹出。
- 必须由用户主动点击原生授权按钮，不能在启动时自动获取手机号或弹出手机号授权。
- 用户可以选择微信提供的号码或在微信授权界面选择其他号码；最终登录号码以服务端兑换结果为准。
- 取消、拒绝授权、缺少 Code、网络异常时保留游客状态，不创建账户，不写入演示 Token。
- 首次建档时保存经过微信验证的登录手机号，自动生成随机昵称，头像字段为空并由客户端显示统一默认头像；无需设置密码或填写资料，直接登录并回到原页面，之后可点击头像修改头像与昵称。
- 同一手机号并发首次登录必须依靠唯一约束和事务复用同一客户，不能生成重复客户或孤立档案。
- 手机号与微信环境均验证成功、客户状态可用后，才记录关联和签发会话。
- 如果手机号能力不可用、额度不足或主体资格未满足，展示明确提示和重试入口，允许继续浏览公开服务；不能退回到手填手机号直接登录或游客下单。
- 本期不接入自建短信验证码登录。手动填写订单联系电话仅供已登录用户履约使用。

### 5.2 访问与回跳

- 首页、分类、搜索、服务详情和已公开服务图片无需客户登录。
- 购物车、地址、订单、客户工单、故障媒体上传、验收和评价必须登录。
- 登录入口记住当前站内页面和必要的非敏感参数，登录成功后恢复页面。
- 回跳只允许小程序内部受支持的路由。
- 登录取消或失败时，不执行原业务写操作。
- 登录后恢复页面和输入内容；创建订单、验收、评价等写操作仍由用户确认提交。
- 游客打开“我的”时展示登录入口，不请求或展示个人业务数据。

### 5.3 登录态恢复与失效处理

- 客户登录态至少保存 `token`、`expiresAt` 和客户基本信息，使用独立客户存储命名空间。
- 已登录用户冷启动时，使用现有 Token 和新的 `wx.login` Code 调用会话环境校验接口；后端同时确认会话有效和当前 OpenID 与该会话一致。
- 环境校验完成前不展示旧客户的个人数据，也不发出个人业务请求。
- 校验成功复用原业务会话，保留原到期时间；正常启动不重复索取手机号，不重复计费，不延长会话。
- 当前微信环境与原会话不同，或会话已过期、被服务端撤销时，清理失效身份并回到未登录状态，需要用户重新点击手机号快捷登录；这属于失效处理，不是用户主动退出或切换账号流程。
- 同一手机号在另一微信环境重新授权登录后可恢复同一账户；不同手机号的独立客户会话分别访问各自数据。跨环境账户复用作为认证规则，不提供客户端主动切换入口。
- 仅有 OpenID 或有效 `wx.login` Code，不能新建手机号客户、恢复已失效会话或静默签发新 Token。
- 前后台切换时检查会话期限；需要重新确认微信环境时执行同一会话校验。校验网络失败时阻止个人数据展示并提供重试，不直接判定账号已变更。
- `wx.checkSession` 不能替代后端会话校验。
- 多个页面并发需要登录或环境校验时共享任务，避免重复弹窗和重复手机号授权。
- 会话过期或被撤销后提示用户重新授权登录，不无限重试，也不静默重新注册。
- 登录成功后持续使用有效会话；“我的”和资料编辑页不展示退出、切换账号或改号按钮。
- 清理小程序本地存储、重新安装或会话到期后，需要重新授权登录；本期不实现用户主动退出后的状态标记及阻止自动恢复机制。

### 5.4 缓存和异步请求

- 订单已读状态等需要持久化的个人缓存按客户 ID 和组织 ID 命名。
- 会话过期、服务端撤销、微信环境校验不一致或本地登录态丢失时，清理个人页面数据、模块级变量和敏感缓存。
- 网络响应回写页面前必须确认请求发出时的身份仍是当前身份。
- 旧身份发出的延迟响应不能覆盖新身份页面；不能自动重放旧身份的写请求。
- 请求、上传和下载封装均处理 401，并使用当前客户会话。
- 上传成功、下载成功和业务写操作的判断不得只依赖网络调用成功，必须检查 HTTP 状态及业务结果。

## 6. 数据模型

本节定义逻辑字段及约束，实际迁移命名和类型沿用项目规范。

### 6.1 复用 `customer`

复用现有 ID、组织、显示名称、手机号、版本和时间字段的结构，清空测试记录后补充：

| 字段 | 规则 |
| --- | --- |
| `status` | `ACTIVE` / `DISABLED`，默认 `ACTIVE` |
| `last_login_at` | 最近成功手机号登录时间，UTC 时间戳；静默环境校验不更新此字段 |
| `last_activity_at` | 最近一次已认证、由用户主动触发的成功业务使用时间，UTC 时间戳 |
| `avatar_media_id` | 可空，关联客户个人头像；空值表示默认头像 |

- 新微信客户的 `source_channel` 为 `WECHAT_MINI`。
- 第一阶段使用 `mobile_cipher` 加密保存规范化登录手机号，使用 `mobile_hash` 查找并建立 `(org_id, mobile_hash)` 唯一约束；创建真实客户时二者必填。
- `mobile_hash` 使用独立服务端密钥计算 HMAC-SHA-256，不能使用可枚举的普通手机号 SHA-256；加密采用带认证的加密算法，密钥仅服务端注入。
- 唯一约束覆盖禁用和软删除客户，避免重新注册绕过账户状态；密钥轮换另行制定一致性迁移规则。
- 补充 `mobile_verified_at` 保存最近手机号兑换验证时间；该字段不表示快速验证组件保证了当次实时验号。
- 客户资料接口不能修改登录手机号；本期不提供更换登录手机号入口。
- `display_name` 保存用户昵称，`avatar_media_id` 保存头像媒体引用；资料成功保存时递增现有 `version`，更新 `updated_at`。
- 个人资料修改不改变客户 ID、手机号、微信环境关联或业务数据归属，不使正常登录会话失效。
- 后台使用统计优先从客户和业务表汇总，不以微信环境绑定数或会话数代替注册人数；活跃更新规则见第 9.5 节。
- 订单联系人和联系电话属于订单快照，与账户资料分别保存。

### 6.2 新增 `customer_wechat_identity`

| 字段 | 规则 |
| --- | --- |
| `id` | 内部主键 |
| `org_id`、`customer_id` | 关联同一组织内客户 |
| `appid`、`openid` | 非空，记录经过 code2Session 验证的微信环境 |
| `unionid` | 可空，当前不作为自动合并依据 |
| `created_at`、`updated_at` | UTC 时间戳 |

通过约束保证关联客户与组织一致，并建立 `(org_id, customer_id, appid, openid)` 唯一约束以避免重复关联。不得对 OpenID 设置“一生只能对应一个手机号客户”的约束。关联仅在手机号快捷登录成功后写入，不能单凭 OpenID 选择某一手机号账户或通过资料修改接口覆盖。

### 6.3 新增 `customer_session`

| 字段 | 规则 |
| --- | --- |
| `id` | 会话主键 |
| `org_id`、`customer_id` | 会话所属客户及组织 |
| `appid`、`openid` | 签发本会话时已验证的微信环境，用于会话恢复校验 |
| `token_hash` | 随机 Token 的 SHA-256 哈希，32 字节且唯一 |
| `expires_at` | UTC 过期时间 |
| `revoked_at` | 可空，服务端撤销时间 |
| `created_at`、`last_seen_at` | 创建时间和最近访问时间 |

- Token 使用密码学安全随机数生成，随机数据不少于 32 字节。
- 明文 Token 只在登录响应下发，数据库和日志不保存明文。
- 会话有效期默认 7 天，由服务端配置；第一阶段不引入 refresh token 和无限续期。
- 每次认证同时验证会话有效性、客户状态、软删除状态和组织一致性。
- 登录生成独立会话，允许同一客户存在多个有效会话；客户端不提供主动退出，过期和撤销仍由服务端控制。
- 客户禁用、删除时所有会话都不能继续使用。
- 客户 Token、师傅 Token 和管理员 Cookie 不得互相用于认证。
- 第一阶段使用手机号专用 Code 兑换方式，无需通过 `session_key` 解密手机号；不持久化或下发该密钥。

## 7. 第一阶段接口契约

沿用项目响应结构：`code`、`message`、`data`、`requestId`。ID 在 JSON 中按项目规范使用字符串，时间采用 UTC ISO 8601 格式。

| 接口 | 认证 | 请求和结果 |
| --- | --- | --- |
| `POST /api/v1/mini/auth/phone/login` | 无客户会话要求 | 请求含 `phoneCode` 和独立的 `loginCode`；成功返回 `accessToken`、`expiresAt`、`isNewCustomer`、`customer` |
| `POST /api/v1/mini/auth/session/verify` | 客户 Bearer Token | 请求含新的 `loginCode`；校验当前微信环境与当前会话一致，返回 `customer`、原 `expiresAt`，不签发新 Token |
| `GET /api/v1/mini/auth/me` | 客户 Bearer Token | 返回 `customer` 和当前会话 `expiresAt` |
| `GET /api/v1/mini/profile` | 客户 Bearer Token | 返回当前客户的 `displayName`、`avatarMediaId`、受保护的 `avatarUrl`、`mobileMasked`、`version` |
| `PUT /api/v1/mini/profile` | 客户 Bearer Token | 请求含 `displayName`、`avatarMediaId`、`version`，只更新当前客户的头像和昵称，返回保存后的资料及新版本 |
| `POST /api/v1/mini/media/avatar` | 客户 Bearer Token | 上传头像图片，返回服务端 `mediaId`；图片归属当前客户，用途为 `CUSTOMER_AVATAR` |

`customer` 第一阶段包含 `id`、`displayName`、`status`、脱敏 `mobileMasked`、`avatarMediaId`、`avatarUrl` 和 `version`。未设置头像时两个头像字段为 `null`，客户端展示默认头像。认证响应不下发完整手机号、AppSecret、微信服务端 access_token、OpenID、UnionID、`session_key` 或其他客户的信息。

头像内容复用受保护的 `GET /api/v1/mini/media/{id}/content`，由带当前 Token 的下载封装获取后展示。`avatarUrl` 不能指向本地临时文件或未经权限校验的公开存储地址。资料读取和更新接口无目标客户 ID 参数，当前客户由会话确定。

资料更新采用完整的可编辑字段快照：`displayName` 必填，`avatarMediaId=null` 表示默认头像，提交原头像 ID 表示保留。未知字段或试图修改手机号、角色、组织、客户 ID 的请求返回校验错误。`version` 不匹配返回 409，不覆盖其他设备已保存的资料。

登录接口不接受明文 `mobile`、`openid`、`customerId`、`orgId` 或 `role` 作为身份依据。`phoneCode` 和 `loginCode` 均须有效；任一验证失败时整体登录失败，不产生新客户或会话。手机号兑换响应按微信官方契约验证 AppID 水印、字段和号码范围。微信服务端 access_token 与 灵狸护家 客户 Token 分别管理，客户端不能接触前者。

本期不注册 `/api/v1/mini/auth/logout` 或客户端账号切换接口；管理员和师傅已有的退出接口不受影响。客户会话过期、账户禁用或服务端撤销仍返回失效结果，客户端清理缓存并引导重新授权。

### 7.1 错误约定

| HTTP 状态 | 业务码 | 场景 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | `phoneCode` 或 `loginCode` 缺失、请求格式不合法 |
| 400 | `PHONE_NUMBER_UNSUPPORTED` | 平台返回的号码不属于第一阶段支持范围 |
| 401 | `PHONE_LOGIN_FAILED` | 手机号授权 Code 无效、过期、已消费或兑换结果验证失败 |
| 401 | `WECHAT_LOGIN_FAILED` | 微信拒绝独立登录 Code，例如过期或已消费 |
| 401 | `CUSTOMER_WECHAT_CONTEXT_CHANGED` | 会话校验的当前微信环境与原会话不一致，需要重新手机号登录 |
| 401 | `CUSTOMER_SESSION_INVALID` | 缺失、伪造、过期、撤销或不属于可用客户的会话 |
| 403 | `CUSTOMER_ACCOUNT_UNAVAILABLE` | 手机号已验证，但该组织内客户被禁用或软删除 |
| 404 | 使用现有资源不存在业务码 | 资源不存在或不属于当前客户 |
| 409 | `RESOURCE_VERSION_CONFLICT` | 资料版本已变化，需刷新后重新编辑 |
| 429 | `RATE_LIMITED` | 登录请求超出限流规则 |
| 503 | `PHONE_LOGIN_UNAVAILABLE` | 手机号能力无资格、无额度、未配置，或微信兑换服务暂不可用 |
| 503 | `WECHAT_LOGIN_UNAVAILABLE` | 微信环境校验超时、网络失败或暂不可用 |

- 上游错误转换为受控错误信息，不原样返回含凭据的请求 URL 或响应。
- 登录 Code 和手机号 Code 各自只能消费一次。失败重试须取得新的对应 Code；手机号 Code 重新获取需要用户主动授权，不能自动重复点击或复用旧 Code。
- 微信调用必须有明确超时，建议上限 5 秒；客户端提供重试入口。
- 登录接口需有基础限流，具体阈值按部署规模配置。

## 8. 用户数据隔离规则

### 8.1 统一原则

- 后端根据会话构造 `Principal{OrgID, SubjectID=customer_id, Role=CUSTOMER}`。
- 私有资源访问同时匹配当前组织和当前客户。
- 列表、详情、创建、修改、删除、状态操作、上传和下载都必须执行权限校验。
- 服务端不能先按资源 ID 读取或修改，再仅依靠客户端过滤结果。
- 子资源通过父资源验证归属；加入其他业务记录的媒体 ID 也必须检查权限。
- 写操作的归属校验和修改必须在同一事务或受归属条件约束的 SQL 中完成。
- 客户不能通过本地角色切换、请求头、请求体、URL 或 Storage 值获得师傅或管理员权限。

### 8.2 资源与操作矩阵

| 资源与接口范围 | 必须校验的关系 |
| --- | --- |
| 购物车及购物车项查询、数量修改、故障信息、删除 | `shopping_cart.org_id + customer_id`，购物车项属于该购物车 |
| 地址列表、新增、编辑、删除、默认地址 | `customer_address.org_id + customer_id` |
| 个人资料读取、更新 | 会话中的组织及客户，仅更新允许的头像和昵称字段 |
| 头像上传、读取、保存引用 | `owner_type=CUSTOMER`、当前组织及客户、用途 `CUSTOMER_AVATAR`，且媒体状态可用 |
| 订单创建 | 从当前客户购物车创建，写入会话客户 ID |
| 订单列表、详情、再次下单 | `customer_order.org_id + customer_id` |
| 工单详情、进度、验收、评价 | 工单关联订单属于当前组织及客户 |
| 故障媒体上传、读取、引用、删除 | `owner_type=CUSTOMER`、当前组织及客户，且满足用途和关联状态规则 |
| 完工证据读取 | 工单关联客户订单，且证据标记允许客户查看 |
| 下单幂等记录 | 当前组织、客户角色和客户 ID 共同限定幂等作用域 |
| 公开服务目录及媒体 | 只允许已发布服务及明确公开的商品媒体；私有媒体不能通过公开路由访问 |

- 同样的幂等 Key 被不同客户使用，不能取得其他客户的结果。
- 评价接口必须新增工单归属检查，并验证对应完工提交及可评价状态；不得仅检查 `Role=CUSTOMER`。
- 验收和评价沿用已有业务状态约束，登录改造不能绕过版本冲突、重复提交或流程检查。
- 客户不能通过更换订单 ID、工单 ID、地址 ID、购物车项 ID 或媒体 ID 读取和操作其他人的数据。
- 管理员和师傅按各自现有业务权限访问客户数据，不复用客户接口的认证身份。

## 9. 点击头像编辑个人资料

### 9.1 入口与编辑页面

- “我的”页展示当前客户头像、昵称及脱敏手机号，头像区域提供明确的可编辑提示。
- 已登录客户点击头像进入个人资料编辑页，建议路由为 `pages/profile/edit`；点击昵称或资料区域也可进入同一页面。
- 游客点击默认头像时先进入手机号快捷登录，登录成功后回到资料编辑页。
- 编辑页包含头像、昵称、“保存”按钮，以及只读的脱敏登录手机号；可编辑范围为头像和昵称。
- 进入编辑页读取当前服务器资料与版本，显示已有头像及昵称。
- 修改先保存在页面草稿中，选择头像和输入昵称不会立即改写服务器客户资料。
- 未保存返回时，存在改动则提示“放弃修改”或“继续编辑”；没有改动时直接返回。
- 默认头像和随机昵称可正常使用，首次登录直接返回原页面，不强制填写资料。

### 9.2 头像选择与上传

- 点击编辑页头像，调用微信 `chooseAvatar` 能力，由用户选择头像；选择取消时保留原头像。
- 新头像先在本页预览，用户点击“保存”后上传到头像接口，取得服务端媒体 ID，再提交资料更新。
- 只接受 JPEG、PNG、WebP 图片，单张不超过 5 MB；服务端按实际文件内容检测类型并验证图片可解码，不能仅依靠扩展名和客户端声明。
- 头像媒体归属当前客户，用途固定为 `CUSTOMER_AVATAR`，不自动进入公开商品媒体或故障证据。
- 资料保存时校验媒体组织、所有者、用途和状态；不能引用其他客户头像、故障图片、工单证据或任意外部 URL。
- 微信选择返回的临时路径仅用于预览和上传，不能作为持久化头像地址。
- 上传或资料提交失败时保留可恢复的编辑草稿，提示重试；重试可复用已上传且仍可用的当前客户头像 ID。
- 头像上传成功但资料保存失败时，原头像保持有效，新媒体作为未关联对象按保留期清理。
- 替换头像先提交新引用，旧文件由媒体回收机制在确认不再引用后清理，不能先删除原头像。
- 默认头像不是私有媒体；已被客户资料引用的头像不能通过媒体删除接口直接删除。

### 9.3 昵称与保存行为

- 昵称使用微信 `nickname` 输入能力，支持微信昵称快速填写和手动编辑；选择头像不要求再次授权手机号。
- 昵称去除首尾空白后为 1～32 个 Unicode 字符，不允许空值、控制字符和换行；无需全局唯一。
- 按微信能力完成头像昵称的内容安全检测，只提交检测通过的最终结果；服务端独立执行字段校验，不单凭输入事件就认为内容有效。
- 客户点击“保存”时先完成必要头像上传，再携带资料版本提交头像与昵称；服务器事务更新二者，避免头像已换而昵称未保存的半完成状态。
- 保存期间防止重复点击；成功后更新本地客户信息和“我的”展示，提示保存成功并返回“我的”。
- 保存失败时不显示成功、不覆盖已保存资料；版本冲突时提示重新加载，不自动覆盖其他设备的修改。
- 修改昵称只影响当前客户资料和后续使用资料的展示，不改写已有订单联系人或历史业务快照。
- 重新进入小程序或同手机号在其他设备登录时，展示服务器最新头像和昵称。
- 登录失效或微信环境校验不一致时清理编辑草稿；重新授权后，旧会话的上传或保存结果不能写入当前页面与缓存。

### 9.4 订单联系电话

- 第一阶段手机号快捷登录已保存登录手机号，编辑资料页展示脱敏号码且不提供改号入口。
- 下单默认优先使用所选地址中的联系人及联系电话；无地址电话时可由后端按当前客户账户手机号提供履约表单默认值，用户可以改为家人或其他联系人。
- 订单联系电话作为订单快照保存，客户可手动填写或修改，不影响登录手机号或订单归属。
- 订单联系电话不能作为登录凭证、账户合并或订单访问权限依据，手填电话不能标记为微信验证手机号。
- 手机号能力资格、额度与隐私授权交互在第一阶段上线前完成。
- 客户资料编辑和订单联系电话编辑使用独立表单，不能通过编辑联系人信息修改账户资料或权限归属。

### 9.5 后台用户管理：注册人数与使用情况

#### 9.5.1 模块与范围

- 在 React 后台将 `/customers` 占位页改为“用户管理”，展示手机号快捷登录注册的小程序客户。
- 现有 `/settings/users`“后台用户”继续管理管理员账号，师傅继续由师傅管理模块负责；这些账号不计入小程序注册人数。
- 首期提供查看、搜索和使用统计，不提供后台新增小程序客户、修改其头像昵称、账号改号、删除、启禁用、导出或代登录操作。
- 当前单组织部署下该模块显示当前平台注册情况；多组织时只显示当前管理员会话组织的数据。平台超级管理员同样遵循当前组织上下文，不自行接受客户端任意组织 ID 查询。

#### 9.5.2 页面与筛选

- 顶部统计卡展示累计注册用户、今日新增、近 7 日新增、今日活跃、近 7 日活跃、近 30 日活跃，并显示统计截止时间及“北京时间”说明。
- 统计卡使用当前组织总体口径，不随列表昵称、手机号、状态或注册时间筛选变化，标题明确为“平台概况”；列表另外展示“符合筛选条件的用户数”。
- 用户列表支持客户 ID 精确查找、昵称模糊搜索、完整登录手机号精确查找、账号状态、注册日期区间和是否下过单筛选。
- 手机号精确搜索经服务端规范化后使用 HMAC 检索，不开放基于明文手机号的模糊扫描，列表显示脱敏手机号。
- 列表列包含客户 ID、头像、昵称、脱敏手机号、账号状态、注册时间、最近手机号登录、最近活跃、累计订单数、已完成订单数、累计已付金额和查看详情。
- 默认按注册时间倒序，支持最近活跃和累计订单数排序，均追加客户 ID 作为稳定排序条件；默认每页 20 条，最大 100 条。
- 零用户、无筛选结果、无使用记录、加载失败等状态提供明确文案；未知或未发生的时间显示“暂无”，数量与金额显示 0。
- 点击详情打开页面或抽屉，查看基本资料、使用汇总及最近订单；头像通过专用管理员受保护接口加载。
- 用户详情不展示完整登录手机号、OpenID、UnionID、授权 Code、Token、密钥或后台不需要的地址明细。
- 最近订单支持独立分页；有现有 `order.view` 权限时可进入订单详情，否则不加载订单明细和对应入口。

#### 9.5.3 统计口径

全部指标限定当前组织，时间存储为 UTC，按 `Asia/Shanghai` 日界线计算；接口以服务器时间作为 `asOf` 截止时间。

| 指标 | 定义 |
| --- | --- |
| 累计注册用户 | 真实手机号建档的客户账户总数，按客户 ID 去重，含禁用及软删除账户；不含管理员、师傅、游客、演示种子、会话和微信环境关联 |
| 今日新增 | 北京时间今日 00:00 至 `asOf` 首次建档客户数 |
| 近 7 日新增 | 含今日及之前 6 个自然日首次建档客户数 |
| 今日、近 7 日、近 30 日活跃 | 指定自然日窗口内 `last_activity_at` 落入范围的不同客户数；近 30 日含今日及之前 29 日 |
| 累计订单数 | 该客户成功创建的订单数，包含取消订单，不含失败或幂等重复请求 |
| 已完成订单数 | 当前订单状态为 `COMPLETED` 的客户订单数，不按工单数累加 |
| 取消订单数 | 当前处于取消状态的客户订单数，按现有枚举映射 |
| 最近下单时间 | 最近成功创建订单的 `created_at`，无订单为空 |
| 累计已付金额 | 客户订单已记录的 `paid_amount` 合计；不是订单报价总额，不视为已核实的银行或微信支付流水 |
| 地址数、购物车项数 | 当前客户保存的地址记录数及购物车项目记录数，仅用于详情汇总；购物车项数不等于商品数量之和 |

- 总体活跃统计含统计窗口内使用过业务的禁用账户，但不含已软删除账户；列表默认不展示软删除客户，可按权限允许的状态筛选查看其脱敏汇总。
- 订单数和已付金额由订单事实记录汇总，多个订单项、工单或媒体关联不能放大计数和金额。
- 用户主动成功登录、打开需要认证的业务页面、成功执行地址/购物车/订单/验收/评价操作、读取或保存个人资料计为一次使用，更新 `last_activity_at`。
- 只有页面处于前台且由用户进入页面或主动刷新发出的认证读取请求计入页面使用；自动轮询、预取、冷启动静默校验、后台请求、图片下载和管理员查看不更新客户活跃。
- 实现允许在认证业务请求中传入受控的前台交互标记；后端仍验证会话及对应路由，标记只用于分析，不参与身份或权限判断。
- 服务器生成活跃时间，不采用客户端时间；高频访问可按每客户至多每分钟一次节流落库，窗口计数误差上限注明为一分钟。
- 每日仅为恢复会话发出的 `session/verify`、`auth/me` 不算手机号登录，也不单独记为活跃。
- 本期不做游客访问次数、停留时长、点击路径、留存曲线或历史逐日 DAU 趋势；最后活跃字段可回答当前滚动窗口人数，不能据此重建历史每日活跃。
- 金额接口统一按项目现有数值表示，前端格式化为人民币；未记录付款为 0，不把无支付接入视为未知的真实支付额。

#### 9.5.4 后台接口与权限

所有接口位于 `/api/v1/admin`，使用现有管理员会话及 Casbin 授权，不接受客户 Token。

| 接口 | 权限 | 结果 |
| --- | --- | --- |
| `GET /customers/overview` | `customer.view` | 注册及活跃卡指标、`asOf`、统计时区和窗口定义 |
| `GET /customers` | `customer.view` | 搜索筛选分页列表及筛选后的 `total` |
| `GET /customers/{id}` | `customer.view` | 当前组织客户脱敏资料及使用汇总 |
| `GET /customers/{id}/avatar/content` | `customer.view` | 该客户当前头像，仅允许当前组织内客户头像媒体 |
| `GET /customers/{id}/orders` | `customer.view` 且 `order.view` | 当前客户的分页最近订单，进入完整订单详情仍沿用现有订单权限 |

- `customer.view` 为独立菜单权限，路由 `/customers`；在角色与权限页面可分配，不因管理员已有 `order.view` 就自动拥有用户管理权限。
- 内置租户管理员初始化应包含该权限，已有内置角色在迁移时更新，新组织创建时也正确赋权；自定义角色由管理员明确分配。
- 接口缺少权限返回 403；当前组织下资源不存在或目标为另一组织客户返回 404。
- 后台头像不复用公开媒体地址，也不向运营人员额外授予通用媒体管理权限；通过当前组织客户资料引用验证其可读性。
- 查询参数、分页上限和排序字段在服务端白名单校验，手机号搜索值和完整个人信息不能进入普通请求日志。
- 本期只读，已有操作审计机制保持不变，不新增账号状态操作接口。按现有日志规范保留内部客户 ID、操作者和请求 ID 等必要访问诊断。

- 登录页不把手机号快捷授权误描述为运营商自动读取本机 SIM 号码；用户使用的是微信授权界面选择的号码。
- 快速验证组件不保证每次实时验号；需要当次实时核验的账户恢复或高风险操作应另行接入微信实时验证能力或经验证的短信流程，本期没有这些自助入口。
- 第一阶段实施完成后移除小程序自动注入 `local-customer-1` 的行为，并移除日常客户认证中的演示 Token 接受路径。
- 本地和体验版使用真实微信身份验证两个客户账户；开发者工具及真机分别验证。
- 自动化测试可替换微信网关为受控测试桩，不能在日常运行接口增加任意客户 ID 登录能力。
- 日志保留请求 ID、受控错误码和必要诊断信息；不记录任一种 Code、业务 Token、微信 access_token、AppSecret、手机号密钥、`session_key` 或完整手机号。
- 生产接口使用 HTTPS，配置请求、上传和下载的合法域名。
- 配置变化需同步 `.env.example`、部署配置和本地启动文档；示例仅列配置名和占位值。

## 11. 上线前测试数据清空与初始化

### 11.1 处理原则

- 小程序尚未上线，现有客户和关联业务数据视为开发、联调产生的测试数据，直接清空。
- 清空全部已有客户记录，包括共享演示客户 1；真实用户首次手机号授权登录时自动创建新客户。
- 不实施旧客户绑定、历史订单认领、归属核实或业务数据转移流程。
- 清理必须作为第一阶段上线前的一次性初始化操作，明确记录执行结果；不得在服务启动、用户登录或日常数据库迁移时反复清空数据。
- 清理期间暂停客户业务写入，数据库清理成功后再开放真实手机号快捷登录和业务操作。

### 11.2 清理范围

| 数据类别 | 清理要求 |
| --- | --- |
| 客户账户 | 清空现有客户、客户微信身份绑定和客户会话；新表尚未创建时按实际部署顺序处理 |
| 客户个人数据 | 清空地址、购物车、购物车项及故障信息关联 |
| 订单及履约数据 | 清空客户订单、订单项、媒体关联及其工单、工单项、派单记录、状态历史、事件、完工提交、证据、审核、验收、评价、客服确认等依赖记录 |
| 请求及流程关联 | 清理客户下单幂等记录及依赖上述测试订单、工单的其他业务记录，避免留下孤立数据或旧请求结果 |
| 私有媒体 | 删除测试客户头像、故障媒体、测试工单证据及其关联记录，并清理对应本地文件或对象存储对象 |
| 客户端缓存 | 清理旧演示 Token、客户资料、订单已读状态、地址、购物车、下载的私有媒体和页面内存缓存 |

- 实施前根据实际表关系列出删除顺序，覆盖直接与间接依赖，不能只删除 `customer` 或订单主表。
- 数据库清理在事务内按依赖顺序执行，并检查清理后的记录数和孤立引用。
- 媒体文件删除与数据库事务分别处理，形成待删除对象清单并支持重试；只删除已确认属于本次测试业务的对象。
- 服务目录、SKU、公开商品媒体、组织配置、管理员账号和权限、师傅账号与工种技能档案保留，清理范围限定为客户测试业务及其依赖。
- 仍被保留的服务目录或商品引用的媒体不能删除；不得通过删除整个媒体目录、清空整个数据库或未核查的级联删除完成清理。
- 自增序列不要求从 1 重置，后续逻辑不能假定新客户 ID 为 1。

### 11.3 初始化与约束

- 初始化脚本停止自动创建共享演示客户及其购物车、地址、订单和媒体；自动化测试数据只在受控测试环境按需创建。
- 空数据库初始化后，客户身份只通过真实手机号授权登录或受控测试夹具创建。
- 当前客户端升级时移除旧演示 Token 和旧个人缓存，不将旧缓存关联到新客户。
- 新增绑定和会话必须通过唯一约束、外键或等效数据库约束保证客户与组织一致。
- 清空测试数据后核对新增约束，订单、工单等业务表的结构和后续业务功能保持完整。

## 12. 第一阶段验收标准

### 12.1 手机号登录与账户

1. 用户授权手机号 A 首次登录生成一个客户，记录微信环境并返回有效会话；登录注册合一，无密码或额外注册表单。
2. 同一手机号重复授权、清理缓存、换设备或另一微信环境授权后，均复用同一客户并恢复其数据。
3. 不同手机号 B 创建不同客户，个人业务数据为空；通过独立测试会话验证各自数据归属，不设计客户端账号切换操作。
4. 同一手机号并发首次登录不会重复建档；任一微信兑换失败都不创建客户或会话。
5. 缺失、无效、过期、已消费或混用的 Code 被拒绝；前端提交明文手机号不能登录。
6. 拒绝隐私确认、取消或拒绝手机号授权时保持游客状态，不创建账户，不执行业务写操作。
7. 伪造、过期、撤销 Token、师傅 Token 和管理员 Cookie 均不能通过客户认证。
8. 会话过期或被服务端撤销后，旧 Token 无效，客户端清理登录态并引导重新授权手机号；不显示退出或切换账号入口。
9. 禁用或软删除客户不能登录，也不能使用已有会话；另一微信环境不能重新注册同一手机号绕过状态。
10. 会话有效且微信环境一致时恢复登录，不重复请求手机号或延长有效期；微信环境变化要求重新授权手机号。
11. 仅提供 OpenID 或 `wx.login` Code，不能登录、注册或恢复过期会话。
12. 手机号授权无资格、额度不足、网络异常时展示明确提示，可继续游客浏览，不能手填手机号直接取得账户。
13. 数据库手机号加密、检索唯一约束生效，接口与日志没有完整登录手机号、授权 Code、密钥或 Token 泄露。

### 12.1.1 头像与昵称编辑

1. 已登录客户点击“我的”头像进入资料编辑页，正确展示已保存的头像、昵称和只读脱敏手机号；游客先登录再进入。
2. 可使用微信头像选择和昵称填写能力修改资料，允许只改头像、只改昵称或同时修改。
3. 保存成功后“我的”立即显示新资料，重启小程序及同手机号在另一设备登录仍显示最新资料。
4. 取消头像选择、放弃编辑或未保存退出不会改变服务器原资料；有改动时返回提示放弃或继续编辑。
5. 空昵称、超长昵称、控制字符、非图片、超过 5 MB 或不可解码图片被拒绝，资料保持完整。
6. 上传失败、资料保存失败和网络异常时可重试，不虚假显示成功、不丢失原头像、不留下半更新的客户资料。
7. A 不能读取或引用 B 的头像，不能通过资料接口修改 B 的昵称、头像、手机号、组织或角色。
8. 不同设备同时编辑产生版本冲突时返回 409，不覆盖已保存的新资料。
9. 登录会话正常保持，客户 ID、订单归属、登录手机号和已有订单联系人快照不因头像昵称变化而改变。
10. 登录失效及重新授权后，旧编辑草稿、异步上传或保存响应不会污染当前会话资料。

### 12.2 业务数据隔离

1. A、B 分别创建购物车、地址和订单，列表、详情、计数互相隔离。
2. A 携带 B 的资源 ID 不能读取、修改、删除 B 的地址和购物车项。
3. A 不能查询或再次下单 B 的订单，不能查看 B 的工单和流程。
4. A 不能验收或评价 B 的工单，失败请求不新增记录且不改变工单状态。
5. A 不能读取、删除或在自己的购物车和订单中引用 B 的故障媒体。
6. 客户只能读取自己的工单中允许客户查看的完工证据。
7. 私有媒体不能通过公开媒体路由被读取。
8. A、B 使用同一幂等 Key 下单，结果分别属于各自客户。
9. 注入其他 `customerId`、`orgId`、角色或修改本地身份值不能改变实际归属。
10. 使用另一组织的资源 ID 和当前 Token 同样被拒绝。

### 12.3 客户端与回归

1. 游客能浏览公开服务，进入个人业务时触发登录入口。
2. 登录取消不执行写操作，登录成功回到原页面且保留合理的输入内容。
3. 并发请求只触发一次登录任务，登录失败不无限重试。
4. 会话失效或微信环境校验不一致后，“我的”、订单列表、地址和购物车不显示失效会话的个人数据。
5. 旧身份请求的延迟响应不回写新身份页面，也不重放旧业务写请求。
6. 冷启动校验当前会话的微信环境；检测到环境不一致时清理旧会话，重新手机号授权后加载正确账户，不提供小程序内主动更换微信或客户账号功能。
7. 订单已读状态等缓存按客户隔离。
8. 日常环境不再自动写入或接受 `local-customer-1`。
9. 现有管理员、师傅登录与权限、下单、派单、完工和验收链路正常。
10. Go 相关认证与越权集成测试、小程序 TypeScript 检查通过；开发者工具和真机双用户验证完成。
11. “我的”、资料编辑页和登录有效态均无退出、切换账号或改号入口，后端未注册客户 logout 接口。

### 12.4 测试数据清理与初始化

1. 一次性清理后，客户、地址、购物车、订单、工单及其关联测试业务记录均为空，无孤立关联和旧客户幂等结果。
2. 测试私有媒体记录及对应文件完成清理，保留的公开商品媒体可以正常访问。
3. 组织、管理员、权限、师傅档案和服务目录保持可用。
4. 重启服务或再次执行日常结构迁移，不会重建共享演示客户，也不会清空真实手机号客户产生的数据。
5. 两个不同真实手机号授权登录后均从空个人业务数据开始；另验证同一手机号在不同微信环境中登录复用同一客户。

### 12.5 后台用户管理

1. 两个不同真实手机号首次登录后累计注册数为 2；重复登录、多个会话及多个微信环境不增加人数。
2. 注册卡、今日及近 7 日新增、活跃卡按北京时间自然日计算，跨 UTC 日期边界结果正确。
3. 用户主动使用更新活跃；静默校验、自动轮询、预取、后台请求、图片下载和管理员查看不使客户虚假活跃。
4. 用户列表搜索、筛选、排序及分页有效，筛选人数与列表一致；概况卡保持当前组织总体口径。
5. 用户详情展示正确资料、订单数、已完成/取消数量、已付金额、最近下单、地址及购物车项数量；多工单和订单项不会重复累计。
6. 无注册、无订单、无活跃和接口失败等状态显示正确，不展示演示用户或伪造统计。
7. 无 `customer.view` 权限无法访问页面或接口；仅有 `order.view` 仍不能访问用户管理；没有订单权限不暴露最近订单明细。
8. 跨组织客户详情、订单、头像和概况访问被阻止，客户 Token 不能调用后台接口。
9. 登录手机号默认脱敏，查询及错误日志不泄露完整手机号和微信凭据；独立管理员头像接口验证当前客户引用。
10. 用户自行修改头像昵称后，后台刷新可看到最新资料，后台浏览不修改资料或延长客户会话。
11. 软删除和禁用客户按定义分别计入累计注册及活跃口径，列表默认行为符合规格。

## 13. 第一阶段完成定义

第一阶段必须同时满足：

- 手机号快捷登录、自动注册、手机号唯一约束、微信环境关联、会话查询与校验、失效后重新授权完成；无客户退出或主动切换账号接口和入口。
- 客户私有接口全部接入客户会话，并完成归属检查。
- 已知评价越权缺口修复，资源 ID 越权测试覆盖全部私有资源类别。
- 小程序登录入口、回跳、身份恢复、游客状态和缓存清理形成完整闭环。
- “我的”点击头像编辑头像昵称、头像上传与权限校验、资料版本控制、保存反馈及跨设备资料恢复完成。
- 后台用户管理、注册活跃概况、客户列表详情、订单使用汇总、独立权限和组织隔离完成。
- 上线前客户测试数据及关联私有媒体已清空，演示身份和自动种子数据退出日常路径，新用户从空数据状态开始。
- 手机号能力资格、额度和密钥配置就绪，部署及本地文档更新，不同手机号隔离、相同手机号账户复用和相关回归检查通过。

手机号快捷登录、头像昵称编辑、后台用户管理及其数据权限均属于第一阶段必需能力。

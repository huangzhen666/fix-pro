# SPEC-013｜通用服务 SKU 简洁配置与详情展示

**状态：** 核心已实现并完成本地重建；完整微信界面及真机验收待完成<br>
**版本：** V3.0<br>
**日期：** 2026-11-04<br>
**适用工程：** `apps/server-go`、`apps/admin-web`、`apps/wechat-mini`；订单和师傅端涉及商品信息时同步适配<br>
**关联规格：** [SPEC-001](./SPEC-001-SKU购物车下单正向链路.md)、[SPEC-007](./SPEC-007-完工双级审核客户验收与售后争议.md)、[SPEC-009](./SPEC-009-后台用户角色与Casbin权限体系.md)

## 1. 目标与范围

让运营用少量基础信息和两块文字完成维修、保洁、清洗、安装、检测等服务的发布。运营说明实际提供什么，系统负责统一排版。

```text
新增服务 → 填名称、分类、价格和单位 → 上传图片
→ 填服务说明、按需填服务须知 → 预览 → 发布
```

本期只保留基础表单、纯文本内容、固定详情布局、草稿与发布、购物车及订单信息衔接。不增加模板选择、页面装修、富文本编辑器、智能文案生成、服务项目拆分、参数表、案例/对照/FAQ 配置或高级设置抽屉。

仍采用固定单价乘整数数量。不支持起步价、现场报价、阶梯价、自动增项收费、小数数量或规格组合。不同价格或不同服务包分别建立 SKU。

## 2. SKU 内容与字段

后台只有以下业务输入。SKU 编码、状态、版本、组织及创建时间由系统维护。

| 字段 | 建议契约名 | 发布要求 | 输入与展示规则 |
| --- | --- | --- | --- |
| 服务名称 | `name` | 必填 | 非空，最多 60 字 |
| 服务分类 | `categoryId` | 必填 | 选择当前有权限使用的启用分类；从分类入口新增时自动带入 |
| 价格 | `basePrice` | 必填 | 输入元，最多两位小数；服务端存整数分，必须大于 0，沿用现有金额上限 |
| 单位 | `unit` | 必填 | 非空，最多 8 字；提供“次、处、台、小时、㎡、份”等快捷选项，也允许输入 |
| 服务图片 | `coverMediaId`、`galleryMediaIds` | 至少一张 | 一张主图即可发布；最多 5 张附图，顺序为主图后接附图 |
| 服务说明 | `serviceDescription` | 必填 | 非空，最多 5000 字；说明具体内容，以及一份服务包含的范围 |
| 服务须知 | `serviceNotice` | 选填 | 最多 3000 字；说明准备事项、材料责任、额外费用、不适用情况及其他限制 |

长度按去除首尾空白后的 Unicode 字符数计算，不要求凑到 5 字、10 字等文案门槛。服务说明和须知只接受纯文本；保留换行和空行，不执行 HTML、脚本或 Markdown。用户输入的列表符号按文字展示，不要求专门添加列表条目。

不再设置独立的简述、单份定义、购买数量说明、不包含项目、材料责任、售后摘要、质保期限、交付检查和需求采集配置。列表与搜索需要摘要时，由服务说明生成简短展示文本，不增加运营输入框；详情仍显示完整原文。

### 2.1 内容职责

- 服务说明回答“提供什么、包含什么、买一单位对应多大范围”。输入框下提供固定帮助示例，不增加确认项，不自动检查语义或按关键词阻止发布。
- 服务须知回答“购买前要知道什么”。无额外注意事项时可以不填。存在收费或范围限制时，运营应如实填写；系统不根据名称、分类或单位生成限制。
- 不自动填入“免费上门”“包材料”“无色差”“质保一年”等服务承诺。
- 文案只解释已经支持的固定套餐，不产生新交易能力。额外项目必须先确认，并通过平台已有支持的流程处理；本版不自动加价、扣款或扩大订单范围。
- 平台已明确制定的通用客服、售后规则可统一展示；不要求每个 SKU 重复录入，不为本版新增政策配置系统。未配置的联系方式和承诺不展示，不能出现无效客服按钮。

### 2.2 图片规则

- 复用现有图片上传、权限归属、安全检查和数量/文件限制；本版不增加商品视频。
- 可上传图片，或在已有的、经审核可用于商品展示的分类封面中选择。不存在可用分类封面时，只显示上传入口；不新增素材库建设要求。
- 使用分类封面属于运营主动选择，不能静默补图来绕过发布检查，也不能把通用插画标注成真实服务案例。
- 调整主图和附图顺序可以直接完成；不要求为图片填写标题、说明或效果提示。
- 上传中或上传失败的图片不算有效素材。已发布图片及订单快照引用的图片，继续受到现有引用保护。

## 3. 后台交互

### 3.1 单页表单

按以下顺序展示，不使用分步向导：

1. 基础信息：名称、分类，价格与单位同排。
2. 服务图片：主图及选填附图。
3. 服务说明：一个多行文本框，带简单填写示例和字数上限。
4. 服务须知：一个多行文本框，明确标注“选填”。

页面底部保留“保存草稿”和“发布服务”；已发布商品编辑时为“保存草稿”和“发布更新”。预览直接使用当前输入，不要求先保存。宽屏可并排显示预览，窄屏使用“编辑／预览”切换，不增加配置项。

删除模板选择、候选项目勾选、更多设置、增强内容以及独立政策编辑等入口。服务单位快捷选项不是模板，不绑定隐藏业务规则。

### 3.2 草稿保存

- 新增后即使没有名称、价格、图片或说明，也允许保存草稿；列表显示“未命名服务”等系统占位，不能把占位当正式文案发布。
- 已填写的数据仍检查类型、金额精度、长度上限、素材权限等有效性；尚未上传完成的图片不写入有效图片列表。
- 保存草稿不触发发布必填校验、不弹出承诺确认，不改变当前线上内容。
- 保存失败保留输入和已成功上传的图片，明确提示原因，可直接重试。离开有未保存改动的页面时提醒一次。

### 3.3 发布与错误提示

- 发布仅检查第 2 节必填项及输入有效性，不校验旧 `detailProfile` 中任何字段。
- 前后端采用相同规则；前端一次展示所有已知问题，服务端也返回可定位到字段的错误集合。运营看到中文提示，不看到内部字段路径。
- 顶部显示“还有 N 项未完成”，每项可点击定位，字段附近同时显示原因。
- 数组素材失败等异常需说明是哪张图；网络、权限或版本冲突与内容缺项分开提示，避免反复修改无关文案。
- 正常首次发布不再增加完整详情确认弹窗。点击一次“发布服务”即可完成校验和发布，过程中防止重复提交。
- 发布失败保留全部输入，展示准确状态：草稿已保存则说明“草稿已保存，发布失败”；不能误报已上架。
- 编辑已发布内容继续保持草稿隔离。发布价格、单位、服务说明或须知变更时，仅一次展示变更摘要供确认；不再次要求逐项勾选承诺。
- 并发编辑冲突明确提示刷新并核对，不静默覆盖他人的修改；客户端保留未保存输入供对照。

## 4. 小程序固定展示

```text
图片区域（单图或轮播）
服务名称
价格／单位、数量与小计
服务说明
服务须知（有内容才显示）
已有平台统一客服／售后入口（有有效能力才显示）
底部购买操作
```

- 图片采用统一比例和圆角；一张图片不显示多图指示器，不重复图片凑轮播。
- 服务说明使用固定标题、正文间距和行距，支持原文换行；不把段落自动拆成项目卡或生成图标。
- 服务须知采用浅色提示卡，与服务说明有明确层级。为空时整块隐藏，不出现“暂无”或空白卡片。
- 正文至少 14px，长内容自然换行，不截断须知、不横向滚动、不使用内嵌滚动框。
- 图片加载失败时显示统一占位，文字、价格和购买操作仍正常可用。
- 320、375、430px 宽度下无横向溢出，底部操作保留安全区；沿用当前产品视觉规范。
- 购物车继续展示商品名称、图片、价格、单位、数量、小计；结算支持查看本次成交版本的完整说明和须知。
- 不增加强制“已阅读须知”勾选项。关键限制通过可见文案说明，不靠额外弹窗补救内容不可见的问题。

## 5. 统一交易与客户资料规则

取消逐 SKU 可配置数量和需求收集规则，避免将简化表单变成仅隐藏复杂字段的外壳。

- 所有 SKU 默认数量为 1，每次增减 1；统一整数范围 1～9999，沿用服务端金额上限。超限明确报错，不静默截断。
- 价格为 `basePrice × quantity`，服务端校验数量和金额；面积、小时、台等单位只用于表达计价口径，不按单位名称触发隐藏规则。
- 有最低时长、固定面积或最少起订要求的服务，建立固定套餐并在服务说明中写清，例如“2 小时保洁套餐，100 元／份”；本版不提供逐 SKU 起订门槛或小数数量。
- 结算统一保留“补充需求（选填）”及“现场图片／视频（选填）”，复用现有资料上限和安全上传能力。客户不填写也能下单，维修、保洁、检测都不因旧规则被拦截。
- 联系人、手机号、服务地址等已有订单必填规则不变。选填资料取消逐 SKU 必填，不影响上传归属和安全校验。
- 保留同 SKU/版本的购物车合并、独立直接下单及重复提交保护。版本变更后继续要求明确确认最新内容，不能只检查价格而忽略服务说明和须知的变化。
- 计价数量不自动等于履约拍照对象数。新模型不再依赖 SKU 的 `aggregation`；本版新订单按订单项的一次服务要求一组前后凭证，可补充更多证据，不因购买 80㎡生成 80 个必拍位置。成交数量、金额和工单工作量保持真实值，现有审核与验收流程保留。

## 6. 数据与接口衔接

### 6.1 目标模型

服务内容直接使用 `serviceDescription`、`serviceNotice` 两个文本字段。移除 V2.2 的 `detailProfile` 及其模板、服务项目、费用、政策、需求规则、增强内容和数量配置；不保留后端隐式必填对象，也不把新文字再转换回旧结构。

草稿允许缺少业务信息；发布必须形成完整、不可变的发布版本。公开列表和详情只能读取发布版本，不能读取未发布草稿。图片读取与删除权限继续以发布及快照引用为依据。

新增、编辑、发布、目录详情和订单相关接口统一使用新契约；移除模板读取等废弃契约。更新 OpenAPI、类型定义和测试夹具，旧字段不能继续作为隐藏的发布条件或双写来源。

### 6.2 成交快照

每个订单项冻结成交时的名称、价格、单位、数量、服务说明、服务须知、图片引用及发布版本。平台通用政策若作为明确的成交承诺展示，也应保留可追溯的版本或内容依据，不增加 SKU 录入项。

客户、后台和师傅侧读取订单信息时使用成交快照。后续编辑、下架或更新服务不能改变已经成交的内容。客户补充需求和现场资料属于订单输入，独立保存，不混入服务说明。

### 6.3 替换策略

本项目按上线前直接重建处理，不开发 V2.2 兼容层、双写或旧内容自动拼接。此前用户已明确允许删除现有 SKU；编写规格时不执行删除；本次实施已完成本地清理，实际计数见执行报告。

实施前重新核对实际订单及明细，不将 2026-10-29 的“无订单”检查视为永久有效。有订单或明细时停止破坏性重建并单独明确处理方案。无订单时，事务内删除当前 SKU、发布版本及其直接关联的购物车/媒体引用等记录，替换旧内容结构；保留账号、分类、权限、地址、技能和媒体原文件。

初始化和测试数据改用简洁模型，不自动发布测试价格或承诺。新草稿不得继续要求选择模板，也不得自动恢复旧字段。

## 8. 验收标准

| 编号 | 场景与通过标准 |
| --- | --- |
| A1 | 后台只有第 2 节输入项，无模板、结构化项目、政策、增强内容或高级规则配置入口。 |
| A2 | 空内容可保存草稿；合法填写后只上传一张主图、不填须知即可发布。 |
| A3 | 名称和说明等允许有效短文本，不因旧最少字数限制失败；长度超限、价格精度及无效图片准确提示。 |
| A4 | 缺多个必填项时，一次列出全部问题并支持定位；修正后可一次发布，不逐次暴露旧隐藏字段错误。 |
| A5 | 正常首次发布无需额外确认弹窗；变更承诺的更新只确认一次；发布失败保留输入且不误报成功。 |
| A6 | 草稿与线上隔离、并发冲突和失败重试正常；离开有未保存改动的页面有提醒。 |
| B1 | 维修、保洁、面积套餐、检测均可使用同一表单完成发布及下单，无服务类型专属校验。 |
| B2 | 小程序固定显示图片、名称价格、说明和选填须知；单图、空须知、长文本和图片失败均有正确效果。 |
| B3 | 320/375/430px 无溢出，正文可读、底栏不遮内容；文字原样换行，HTML/脚本不执行。 |
| B4 | 客户不填补充需求、不传现场资料也能结算；填写或上传后可正常保存和查看，权限校验仍有效。 |
| C1 | 数量默认 1、步长 1，统一范围和金额校验覆盖加购、修改数量、合并、直接下单及购物车结算。 |
| C2 | 服务说明或须知变更即使价格不变，也触发购物车版本确认；旧客户端不能绕过服务端校验。 |
| C3 | 成交后修改或下架商品，客户、后台及师傅仍读取原成交说明、须知和价格；素材引用受到保护。 |
| C4 | 面积/小时数量不会生成等量必拍位置；一次服务留证规则可完成提交，计价数量不被改写。 |
| D1 | 实施核对无订单后才重建；清理范围、事务失败回滚和保留数据有记录，旧字段与模板不被 seed 恢复。 |
| D2 | 新 OpenAPI、数据库、各端类型和运行时一致；不再因任何 V2.2 配置缺失而阻止新商品发布或下单。 |

验证应包含四类服务的后台配置、发布及小程序下单实测，记录基本表单截图和失败提示；构建通过不能替代真实交互验收。简单成功路径为：完成必填内容 → 点击一次发布 → 小程序可购买。

## 1. 交付目标与边界

完成如下最短路径：

```text
新增服务 → 名称、分类、价格、单位、图片、服务说明
→ 按需填写服务须知 → 点击一次发布 → 小程序可购买
```

后台只提供 SPEC 第 2 节字段；服务说明必填、服务须知选填，一张主图即可发布。草稿可以不完整，发布一次列出全部缺项。小程序固定展示图片、名称价格、说明和须知，无须运营装修页面。

本次同时删除当前全部 SKU 和直接关联数据，移除旧 `detailProfile`、模板及全部隐藏配置依赖。保留发布隔离、媒体安全、并发控制、版本确认、订单快照和既有订单/履约流程。

不实现复杂报价、小数数量、SPU、AI 文案、富文本、素材库、平台政策管理、装修组件或新售后系统。已有分类封面和平台客服能力有则复用，无则不新增系统补齐。

## 2. 执行约束与里程碑

- 开始执行时记录工作区改动，保留不属于本任务的代码和数据；旧版已执行迁移不回写，新增迁移编号以实施时仓库为准。
- 清库先在独立测试库验证；实际环境操作前停止旧进程及其他写入入口，重新核对订单/明细为空。不得沿用历史无订单结论。
- 有订单或明细时停止破坏性重建，记录阻塞并单独明确处理方案；其他不依赖实际清库的开发、测试可以继续。
- 正常启动、登录、客户初始化及重复 seed 都不能自动删除 SKU。
- 不重置用户账号或密码，不自动发布测试商品，不把真实素材或连接密钥写进测试报告。
- 未运行、跳过、设备不可用的检查不标记通过；不沿用旧版任务勾选状态。

## 3. P0｜基线与契约

- [x] 记录工作区状态、当前迁移版本、SKU/发布版本/购物车/订单/媒体计数及现有启动方式，只记录必要计数。
- [x] 搜索 `detailProfile`、`enhancements`、模板、简述、逐 SKU 数量/需求规则、`aggregation` 的运行时引用，覆盖服务端、后台、客户和师傅端、OpenAPI、seed 及测试。
- [x] 冻结 SKU 写入/详情/摘要、发布版本、购物车与成交快照 DTO：内容改为 `serviceDescription`、`serviceNotice`；不保留旧对象或双写。
- [x] 统一字段上限、Unicode 计数、空白处理、图片顺序和整数分金额规则；草稿允许缺项，发布按 SPEC 校验完整内容。
- [x] 确定草稿可空的名称、分类、单位、价格如何在数据库和 DTO 表达；“未命名服务”只作 UI 占位，不能填进正式商品绕过校验。
- [x] 定义发布错误集合：稳定错误码及 `errors[]` 字段路径/中文原因；内容、权限、网络、并发冲突区别处理，不只返回第一个缺项。
- [x] 定义保存成功后发布失败、重复点击、首次发布及发布更新的状态与重试行为；保存返回的 ID/版本需立即保留，避免重试重复建档。
- [x] 固定四类隔离测试样例和单图无须知的最小样例，不将示例价格或承诺作为生产默认值。

退出条件：前后端可依据同一契约实现；没有“表面删除输入框、后端仍要求旧字段”的路径。

## 4. P1｜删除旧 SKU、迁移与初始化

### 4.1 清理范围和事务

- [x] 新增一次性迁移，在事务中锁定相关数据并再次断言 `customer_order`、`order_item` 为空；不满足时任何删除和 DDL 都不得生效。
- [x] 删除全部当前 SKU，包含草稿、已发布和已下架；不按名称或是否测试商品筛选。
- [x] 按外键顺序清除这些 SKU 的购物车媒体关联、购物车项、技能/媒体绑定、发布快照媒体引用和发布版本；更新受影响购物车版本，保留购物车容器。
- [x] 删除主数据及订单项中旧结构化内容列/约束，加入说明、须知及其成交快照字段；调整草稿可空约束和统一数量约束。
- [x] 保留账号、分类、权限、地址、技能、媒体资产及原文件；不做无关对象清理。清理后、创建任何新示例前，记录旧 SKU 及其直接关联零残留断言。
- [x] 不改已执行迁移，不还原历史 SKU，不把旧 `detailProfile` 自动拼接成新文本。

### 4.2 初始化和迁移验证

- [x] 移除模板初始化及旧字段写入；开发 seed 改为显式、幂等的新模型草稿创建，不自动运行、不发布、不覆盖运营编辑。
- [x] 普通初始化不带测试价格和虚构承诺；完整演示数据仅允许显式导入隔离测试库。
- [x] 验证已有库完整升级和新建空库完整迁移；复用历史迁移链后仍能应用新迁移。
- [x] 数据库集成验证：有订单拒绝、中途失败回滚、无订单成功清理、保留数据完整及 seed 连续运行两次幂等。
- [x] 明确回退边界：事务失败可回滚；已提交删除不能靠 down 恢复原数据。切换前保存可恢复的必要数据库备份，不在报告保存敏感内容。

退出条件：独立测试库清理可重放，新模型可保存空草稿，旧初始化入口不会恢复旧数据。

## 5. P2｜目录、发布、校验与媒体

- [x] catalog 改用两个文本字段及基础属性，移除模板接口、旧 Profile 校验、简述输入及不再使用的结构化构建逻辑。
- [x] 实现草稿宽松保存：允许缺项，但已填数据检查类型、精度、上限、媒体归属和有效性；保存不触发发布条件。
- [x] 发布一次汇总所有缺项与非法值：名称≤60 字、单位≤8 字、说明≤5000 字、须知≤3000 字，名称/单位/说明只要求非空；价格>0、启用分类、有效主图必需。
- [x] 图片最多 1 张主图＋5 张附图；单图可发布，无图片说明要求，上传中/失败素材不计入有效图片。
- [x] 保持发布事务、并发版本控制和不可变版本；公开目录仅读已发布版本，保存草稿不影响线上。
- [x] 发布内容相同可沿用现有去重机制；说明和须知变化必须进入发布版本比较，不能仅比较价格。
- [x] 更新媒体绑定与快照引用：旧项目图/增强图引用模型退出，发布和订单仍可访问对应图片，未授权用户不能读取草稿素材，已被快照引用的媒体不可删。
- [x] 列表摘要从说明生成展示文本，搜索改用名称/说明；详情返回完整文本，不要求新输入摘要。
- [x] 同步 OpenAPI 请求、响应、错误集合和权限路由，删除模板契约；保留既有 SKU 权限，不扩大权限范围。

退出条件：API 可保存空草稿、一次返回所有发布问题，并发布单图无须知商品；不存在旧字段兜底依赖。

## 6. P3｜交易、成交快照与履约

- [x] 删除逐 SKU min/max/step/aggregation；详情初值 1、步长 1、统一整数范围 1～9999；服务端金额上限继续生效。
- [x] 更新加购、并发合并、修改数量、直接下单、购物车结算及再次购买等入口；超限报错，不静默截断、不按单位名称推导规则。
- [x] 文字和现场资料统一选填：无资料可结算；已提交资料仍校验数量/类型/归属和上传状态。联系人、手机号、地址等订单必填要求保留。
- [x] 保留同 SKU/版本合并、独立直接下单、幂等提交及事务回滚，不能因简化模型使直接下单修改已有购物车。
- [x] 说明或须知发布变更后，购物车标记版本变化；按预期版本明确确认后再下单，确认期间再次更新则拒绝旧确认。
- [x] 订单项冻结名称、价格、单位、数量、说明、须知、图片引用、发布版本；客户、后台和师傅读取成交数据，不回查当前商品替换承诺。
- [x] 盘点现有平台通用政策；若有作为成交承诺展示的内容，保留其可追溯版本/依据；不存在时不造政策、不新增 SKU 字段。
- [x] 履约留证移除 `aggregation` 依赖，新订单按每个订单项一次服务要求一组前后凭证，可追加证据；价格数量、工单工作量和既有审核验收状态机保留。

退出条件：四类商品均可无需求资料完成两种下单路径；版本确认、成交快照和一次服务留证可验证。

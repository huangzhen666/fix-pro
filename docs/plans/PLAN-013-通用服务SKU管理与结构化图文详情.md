## 1. 交付目标与范围

落实“模板驱动的简洁表单＋固定视觉组件”：

```text
删除当前全部 SKU 及直接关联记录
→ 清除旧模型与初始化入口
→ 选模板或通用模板
→ 填五组基础信息、确认业务承诺、上传一张主图
→ 系统物化规则并生成手机预览
→ 发布 → 浏览 / 加购 / 按 SKU 补充需求 → 下单
→ 后台及客户订单查看成交承诺
```

完成条件：

- 常规配置不要求页面装修，不暴露模块类型、卡片样式、颜色、图标或页面排序。
- 只有一张主图、没有流程及案例时，仍有完整的项目卡、费用边界、交付清单和售后卡。
- 补漆、小时保洁、面积保洁、设备检测共用表单、接口与渲染器；面积保洁使用通用模板创建。
- 数量和需求采集规则覆盖浏览、购物车、直接下单、订单恢复购物车等真实入口。
- 物理删除当前全部 SKU（含草稿、已发布、已下架）及其版本、关联和购物车项；不是下架、软删除、归档或导入新模型。账号、分类、技能、地址、权限及媒体文件保留。
- 新模型上线前不保留旧SKU展示、旧字段、兼容接口、双写或旧seed；新服务按模板重新建档，编码、ID与发布版本不承接旧数据。
- 新发布版本和新订单保存不可变承诺；API、数据库、所有消费端与测试夹具一致。

不实现起步价、现场报价、阶梯价、增项支付、小数数量、SPU、排班、页面装修或新的售后执行系统。开发测试示例不自动变成实际上架服务。

## 5. P1｜一次性清理、数据结构和初始化

### 5.1 必做：物理删除当前已经存在的全部 SKU

本步骤是新模型实施的必做项，不是可选清理。目标是在创建任何新样板前，清空当前SKU主数据及其直接业务引用；不保留旧内容作为迁移源。

- [x] 在停止旧写入后记录当前全部SKU及各关联表计数，以清理后零行断言验证全部删除，范围包含草稿、已发布、已下架，不按名称、创建人或是否为测试商品筛选。
- [x] 在同一事务内先断言订单主表与order_item为空；不满足则报错且不删除任何记录。
- [x] 删除旧SKU购物车项媒体绑定及购物车项，更新受影响购物车版本；保留购物车容器和客户。
- [x] 按引用依赖物理删除 `service_sku_skill_requirement`、`service_sku_media`、`service_sku_version` 和 `service_sku` 中全部旧SKU记录；盘点无外键约束的逻辑引用，不能只依赖数据库级联。
- [x] 不以软删除、下架或归档替代物理删除，不将旧SKU转换成新detailProfile，也不重新导入旧版本或承诺。
- [x] 清理后、初始化新样板前验证SKU主表计数为0，旧ID集合对应的版本、媒体/技能关联及购物车引用计数均为0，并写入验收证据。
- [x] 不删除媒体实体及对象存储文件，不删除分类、技能字典、客户、账号、角色、地址或履约数据。
- [x] 清理计数写入受控迁移日志。禁止整库TRUNCATE CASCADE与启动时自动重置。

### 5.2 新结构

- [x] SKU增加非空JSONB detail_profile，数据库验证对象与schemaVersion=1；草稿可仅含schemaVersion。
- [x] 删除三个旧文本列和订单文本快照列，订单项增加非空detail_profile_snapshot，保留基础成交字段。
- [x] fault_description等需求专属命名按契约改为通用命名；媒体关联复用现有机制，不为名称变化重建无关表。
- [x] 购物车及相关SQL数量上限统一为1～9999；数量业务限制仍由发布规则收紧。
- [x] 迁移后旧运行时SQL不再引用被删除列；已有迁移保持可从新库完整执行。
- [x] 明确down迁移只能恢复结构，不能恢复被清理数据；不提供虚假“恢复旧SKU”的回滚路径。

### 5.3 seed与夹具

- [x] 找到并修改旧SKU seed、客户初始化及测试直接INSERT；避免新服务重启后重新插入旧结构。
- [x] 建立四个有效结构化示例夹具；测试初始化幂等生成草稿，不复用旧ID或版本，不自动发布。
- [x] 数据库集成测试使用合法新列和新结构，涉及订单/履约的夹具一并更新。
- [x] 验证已有结构测试库升级、新空库全迁移、事务中途失败回滚、意外存在订单时无数据变化。

### 5.4 清除旧模型与初始化包袱

- [x] 删除运行时三个旧文本字段的DTO、SQL、表单及展示分支，删除旧fault专属请求命名和全局故障资料必填校验；不增加回退读取或兼容别名。
- [x] 移除旧SKU的运行时seed、启动初始化、硬编码商品及旧接口示例，测试数据改用新结构；禁止新应用启动后恢复刚删除的旧SKU。
- [x] 保留已经执行的版本化迁移文件，确保新库可走完整迁移链；历史迁移文件不属于运行时兼容层，不通过删除迁移记录制造断链。
- [x] 清除客户端目录/详情/购物车旧商品缓存及后台编辑态缓存；旧ID返回不存在，不映射到新ID。
- [x] 清理完成后只按新模板重新建立服务。四个示例仅在测试初始化中幂等生成草稿，不自动发布，不恢复旧SKU身份。

退出条件：当前旧SKU及其直接引用物理删除完成，初始化新样板前主表为空；仅影响限定数据；运行时没有旧模型兼容分支或旧seed；完整迁移链、初始化及保护条件有可重复验证结果。

## 7. P3｜交易规则、需求采集和成交快照

### 7.1 数量与金额

- [x] 建立统一数量/金额校验函数：整数1～9999，min/max/step、aggregation、金额上限，服务端是最终依据。
- [x] 覆盖首次加购、同SKU/版本合并、购物车更新、直接下单、购物车结算和订单恢复购物车入口。
- [x] 合并后的总数重新按min+n×step校验；不沿用原SQL的<=99条件，不静默截断/取整。恢复购物车超限或步长不符返回可理解的规则错误。
- [x] 保持直接下单独立于购物车，不合并或清空无关购物车项；并发加购和事务锁不得导致绕过上限。
- [x] 修改价格不影响独立/累加含义；不从单位字符串推断面积、工时、人员和额外费用。

### 7.2 需求、版本和订单

- [x] 统一使用demandDescription/demandMedia，按SKU发布规则处理HIDDEN/OPTIONAL/REQUIRED；不再全局要求故障图文。
- [x] 明确草稿购物车资料可以不完整，最终提交订单时执行必填；先前已填资料不因编辑SKU草稿被自动删除。
- [x] 文字及媒体继续执行归属、权限、长度、类型和数量限制；混合购物车逐项校验，不把保洁要求套用到维修。
- [x] SKU正式发布内容或规则变化时，两条下单路径都要求重新确认，不只比较价格；确认后按新版本再次验证数量与需求。
- [x] 在同一事务写订单、基础成交字段、detail_profile_snapshot和客户需求/媒体绑定；失败全部回滚。
- [x] 客户和后台订单读取成交快照，不能查询当前SKU补内容；订单/工单与恢复购物车的消费逻辑统一新命名。
- [x] 累计额度计价不能按每小时/每平方米生成照片位：按成交aggregation生成凭证位、校验绑定及提交完工；保留订单和工单购买数量，独立对象留证规则不变。
- [x] 盘点师傅端及管理端工单字段；有旧引用则同步类型/标签，维持身份和权限，不扩展现场作业规则。

退出条件：四个示例从API完成两条下单路径；保洁可不上传照片、补漆按配置必须上传；版本变化、恢复购物车及快照原子性测试通过。

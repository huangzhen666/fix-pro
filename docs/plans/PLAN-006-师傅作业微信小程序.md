# PLAN-006｜师傅作业微信小程序实施计划

**状态：** Planned  
**版本：** V0.1  
**日期：** 2026-08-09  
**对应 Spec：** `docs/specs/SPEC-006-师傅作业微信小程序.md`  
**适用工程：** `apps/wechat-worker-mini`、`apps/server-go`、`apps/admin-web`

## 1. 交付目标

交付一个与客户小程序隔离的师傅作业微信小程序，逐步打通：

```text
师傅认证
→ 查看我的工单
→ 接单/拒单
→ 到达并开始服务
→ 上传现场证据
→ 提交完工
→ 管理后台审核
→ 客户小程序查看进度并验收
```

本计划第一阶段先保证独立小程序可导入、可启动、可读取当前师傅工单；后续阶段再按履约状态机扩展真实作业闭环。

## 2. 范围与约束

### 2.1 本计划包含

- 独立微信小程序工程和构建检查；
- 师傅身份认证与组织隔离；
- 师傅工单列表、详情和状态操作；
- 现场图片/视频证据上传；
- 完工提交、管理后台审核和客户侧进度展示；
- 幂等、并发、越权和三端 E2E 验证。

### 2.2 本计划不包含

- 师傅注册、实名认证、银行卡和结算；
- 自动派单、抢单、路线规划和排班；
- 离线作业和弱网断点续传；
- 客户小程序和管理后台的视觉重构；
- 与本链路无关的订单、SKU 或数据库重构。

## 3. 关键决策

1. 师傅端使用独立工程 `apps/wechat-worker-mini`，不复用客户小程序的页面入口和 Token 存储。
2. 开发环境使用 `Bearer local-worker-{workerId}`，生产环境替换为微信登录态换取的服务端 access token。
3. 所有作业状态变化由 Go 后端事务内校验，前端只负责展示和发起命令。
4. 每个状态命令必须支持幂等键；重复请求返回第一次操作结果。
5. 完工证据先上传媒体，再在完工提交接口中绑定；孤儿媒体需要后端清理任务或明确保留策略。
6. 师傅只允许访问当前 `assignee_id` 对应的工单，越权由后端拒绝。
7. 管理后台继续负责派单和完工审核，客户小程序继续负责进度展示和验收。

## 5. F0｜契约和测试骨架

### F0-1｜冻结师傅端状态矩阵

整理以下状态和允许动作：

- `PENDING_DISPATCH`：尚未分配，不出现在师傅端；
- `PENDING_ACCEPT`：允许接单或拒单；
- `PENDING_ARRIVAL`：允许查看预约信息和到达；
- `ARRIVED`：允许开始服务；
- `IN_SERVICE`：允许上传证据和提交完工；
- `WAITING_COMPLETION_REVIEW`：等待后台审核，不允许重复提交；
- `REWORK_REQUIRED`：按规则重新作业或补充证据；
- `WAITING_ACCEPTANCE`、`FINISHED`、`CANCELLED`：只读展示。

验证：每个状态至少有一个允许动作和一个拒绝动作，并映射到后端测试。

### F0-2｜冻结接口和错误码

补齐 OpenAPI 和接口错误契约：

- 师傅工单列表、详情；
- 接单、拒单、到达、开始服务；
- 证据上传、证据绑定、完工提交；
- `UNAUTHORIZED`、`FORBIDDEN`、`WORK_ORDER_NOT_FOUND`、`INVALID_STATUS_TRANSITION`、`RESOURCE_VERSION_CONFLICT`、`IDEMPOTENCY_REPLAY` 等错误。

验证：请求字段、状态码、响应外壳与 SPEC-004 一致。

### F0-3｜准备测试数据

准备：

- 两个组织；
- 两名师傅；
- 待接单、待上门、服务中和待审核工单；
- 图片、视频和超限媒体样本；
- 一个已被其他师傅分配的工单。

退出条件：后续阶段可重复创建测试数据，不依赖人工修改生产数据。

## 6. F1｜独立小程序工程

### F1-1｜工程与导航

完成：

- `apps/wechat-worker-mini` 工程配置；
- `app.json` 三 Tab：工作台、工单、我的；
- TypeScript、WXML、WXSS 基础页面；
- API 基础地址、请求封装和 Token 存储；
- 开发者工具导入说明。

验证：工程导入无页面缺失；三个 Tab 可切换；`npm run mini:worker:typecheck` 通过。

### F1-2｜页面状态规范

所有页面统一实现：

- 首次加载态；
- 空数据态；
- 网络失败态；
- 重新加载入口；
- 状态和错误信息不直接暴露堆栈。

退出条件：AC-006-01、AC-006-02、AC-006-04、AC-006-05 通过。

## 7. F2｜认证与工单读取

### F2-1｜本地认证适配

- 保留 local 环境 `local-worker-{id}` Token；
- 请求统一加 Worker Authorization；
- 无 Token 或 Token 非法时跳转认证错误页；
- 为生产微信登录预留 `loginCode → accessToken` 适配层，不在本期伪造生产登录。

### F2-2｜工单列表和详情

- 接入 `GET /api/v1/worker/work-orders`；
- 增加工单详情页；
- 展示服务地址、预约时间、SKU、客户故障描述和已有证据；
- 所有详情数据由后端按师傅身份过滤。

验证：师傅只能看到自己的工单；无工单显示空态；接口失败可重试。

## 8. F3｜接单与拒单

### F3-1｜后端命令接口

实现接单和拒单命令：

- 状态必须为 `PENDING_ACCEPT`；
- 校验当前师傅仍是被分配人且状态为 `ACTIVE`；
- 拒单必须填写原因；
- 使用 `Idempotency-Key` 和工单 `version`；
- 写入工单状态历史和派单历史。

### F3-2｜师傅端交互

- 工单详情展示“接单”和“拒单”；
- 拒单使用二次确认并要求填写原因；
- 成功后刷新详情和列表；
- 重复点击不得生成重复状态历史。

验证：正常接单、拒单、重复请求、版本冲突、非当前师傅请求全部有明确结果。

## 9. F4｜到达与服务中

### F4-1｜状态操作

支持：

- `PENDING_ARRIVAL → ARRIVED`；
- `ARRIVED → IN_SERVICE`；
- 每个动作要求当前师傅身份、当前状态和版本匹配；
- 记录操作时间和操作人；
- 预约时间展示使用统一时区转换规则。

### F4-2｜页面交互

- 详情页根据状态只展示当前允许动作；
- 到达和开始服务需要二次确认；
- 操作中禁用按钮，成功后刷新；
- 非法状态操作展示后端业务错误。

退出条件：状态机、并发版本冲突和重复点击测试通过。

## 10. F5｜现场证据与完工提交

### F5-1｜媒体上传

- 支持图片和视频；
- 前端限制类型、大小和数量，后端再次校验；
- 上传结果返回媒体 ID，不直接信任客户端 URL；
- 媒体只能绑定当前师傅负责的工单；
- 上传失败支持单个文件重试。

### F5-2｜完工提交

- 完工描述必填；
- 至少一项符合规则的完工证据；
- 提交接口使用幂等键和版本号；
- 成功后状态进入 `WAITING_COMPLETION_REVIEW`；
- 不允许重复提交或跨师傅绑定证据。

验证：图片、视频、超限文件、无证据、重复提交、越权媒体绑定均有测试。

## 11. F6｜后台审核与客户进度

### F6-1｜管理后台

- 履约调度页展示师傅提交的完工证据；
- 支持通过和驳回；
- 驳回必须填写原因；
- 审核后刷新工单状态和操作历史。

### F6-2｜客户小程序

- 客户订单详情展示师傅分配、预约时间、履约状态和完工证据；
- `WAITING_ACCEPTANCE` 展示客户验收入口；
- 客户验收或返工后，师傅端看到最新状态。

验证：

```text
后台派单
→ 师傅接单
→ 师傅到达并开始服务
→ 上传证据并提交完工
→ 后台审核
→ 客户查看进度并验收
```

## 12. F7｜真实环境与发布验收

### F7-1｜并发与幂等

- 两个相同接单请求只有一个成功状态变更；
- 相同幂等键重复请求返回同一业务结果；
- 相同幂等键不同请求体返回冲突；
- 管理后台审核和师傅提交完工并发时状态不被覆盖。

### F7-2｜越权与数据隔离

- 师傅 A 请求师傅 B 的工单返回 403/404；
- 组织 A 的 Token 不能读取组织 B 数据；
- 媒体 URL 不可绕过权限直接读取私有文件；
- 师傅端不能调用管理员接口。

### F7-3｜三端 E2E

在真实 PostgreSQL 环境执行至少一条完整链路，并保留：

- 请求与响应摘要；
- 工单状态历史；
- 媒体绑定记录；
- 后台审核结果；
- 客户验收结果。

最终退出条件：AC-006-01 至 AC-006-06、SPEC-004 相关履约验收及并发/越权门禁全部通过。

## 1. 交付目标与范围

购物车简化为“选择服务、调整数量、移除服务、去结算”。正常服务卡仅保留勾选、图片、名称、单价／单位和数量；底栏保留全选、已选合计及去结算。

实施必须达到：

- 移除购物车里的服务约定、说明／须知展开、备注输入、附件区、补充入口及重复卡片尾。
- 备注统一在确认订单或下单后的订单详情编辑；已有购物车备注和媒体关联完整保留。
- 去结算前只核对所选服务，不再逐项保存未修改的备注，不下载购物车内已不展示的需求资料。
- 保留近期修复的全选完整点击区、底栏层级及结算异常统一复位，避免精简后重新出现按钮点不动。
- 保持真实计价、数量边界、版本确认、勾选结算、登录保护及立即下单的既有规则。

不新增后端接口、数据库迁移、批量管理、推荐服务、费用能力或购物车地址／时间表单。不删除共享需求编辑器、服务内容组件及需求保存接口。

### P1：移除重复内容和前置请求

- [x] 移除 `service-content`、详情展开行、备注输入、媒体缩略图／上传／移除区，以及每项卡片尾的补充与常驻删除按钮。
- [x] 删除顶部“共 N 项服务／左滑服务可删除”专用行及“已经到底啦～”，保留空态和必要异常提示。
- [x] 删除 `expandedId`、`toggleDetails`、`inputDemand`、`blurDemand`、`choose`、`removeMedia`、`persist`、`loadPrivateMedia` 等不再使用的方法及状态。
- [x] 删除购物车对 `saveDemand`、`uploadDemand`、私有媒体 `download` 的导入和调用；删除 `savingId` 等不再成立的禁用条件，避免 UI 永久依赖旧状态。
- [x] `checkout()` 移除逐项 `persist` 循环，只保留所选项目复核、存储所选 ID 和导航，统一 `try/catch/finally` 恢复状态。
- [x] 删除购物车 `index.json` 的 `service-content` 注册；保留公共组件及接口供服务详情、结算和订单详情使用。
- [x] 不写空 `demandDescription` 或空媒体数组来代替删除 UI，不调用媒体删除接口；原有需求仍由后端购物车数据保存，进入结算后按原服务项读取。

产出：购物车正常使用和去结算不再触发需求保存、上传或私有资料下载；已有数据不变。

### P2：重建紧凑服务行及删除手势

- [x] 每项合并为一条服务行：左侧勾选及 56px 图片，右侧名称与“¥单价/单位＋数量控件”；删除逐项小计，保留底部已选合计。
- [x] 使用主题变量、16px 页边距、约 12px 卡片内边距、10–12px 卡片间距；名称最多两行，数量控件复用 `quantity.wxss`。
- [x] 勾选和全选的实际点击范围至少 44×44px；价格与数量在窄屏必要时换行，不挤压控件或裁掉关键金额。
- [x] 服务主图通过 `mediaUrl` 处理相对及绝对地址，失败时显示中性占位；图片失败不阻止其他操作。
- [x] 图片及名称点击进入现有服务详情，沿用真实 `skuId`；加减、勾选及删除区域的事件不冒泡到详情导航。
- [x] 左滑展示删除、右滑收起；保留横纵方向判定，纵向滚动不触发删除区域，滑动结束不能误触详情。
- [x] 长按服务行展示仅一个“删除服务”的操作菜单，复用同一删除函数及一次确认；长按后抑制尾随点击，加减及勾选控件不误触长按菜单。
- [x] 删除取消或失败保留数据及选择；成功后重新计算摘要，删除最后一项后隐藏底栏并进入空态。
- [x] 异常项使用紧凑状态行：下架项不可选、不可增减但可删除；待确认项保留现有查看新版和显式确认能力，不插入原有大块说明或需求表单。

产出：符合 SPEC-016 的正常服务卡、空态及异常项布局；触摸操作互不干扰。

### P3：状态一致性与结算衔接

- [x] 所有选择、数量、删除、版本确认及手势以稳定服务项 ID 定位，替换会因列表变化而失效的事件下标。
- [x] 维护当前页面的选择记录；详情／结算往返及数量更新不重置手动选择，登录身份变化及页面结束时适当清理，不向其他账号沿用。
- [x] 统一计算已选合计、已选服务项数和全选状态；N 为服务项数，不能改成购买数量之和。下架项不计入选择和总价。
- [x] 为购物车读取及写入明确请求序号或等效操作协调：写入开始前的旧刷新不能覆盖写入结果，旧响应不能恢复已删项；导航或页面销毁后的请求不回写旧状态。
- [x] 去结算时锁定本次所选 ID 快照并阻止重复点击，重新读取后核对服务是否仍存在、可用及无需版本确认；失败留在购物车并提示，不自动接受新价或扩大勾选范围。
- [x] 复用 `fixpro.checkoutCartItemIds`；导航失败清理本次跳转参数，并在 `finally` 解除状态锁。无选择时结算禁用，全选仍可操作恢复选择。
- [x] 保留原有全选按钮完整触摸区域和底栏层级；删除旧 `.checkout button` 等会误伤全选按钮的通用选择器，分别控制全选和结算样式。
- [x] 通过自动化验证已有文字及图片／视频 ID 在确认订单“备注”编辑器回显、更新；实际客户端仅验证进入确认订单及备注入口，真实资料链路待补验。
- [x] 确认“加入购物车”仍只加购、“立即下单”仍独立结算；购物车改造不修改这些入口的业务语义。

产出：完整的选择、调整和勾选结算链路；旧表单移除后没有残留禁用状态或资料丢失。

## 5. 执行与回退边界

1. 本期是客户小程序前端调整，沿用现有本地服务，不执行数据库迁移、订单重置、账号重置或媒体清理。
2. 先删除无用逻辑和请求，再接紧凑布局及手势，最后做完整回归；不要只隐藏旧表单而保留其前置请求及禁用条件。
3. 如需回退，只回退本次购物车及相关回归调整，不覆盖 PLAN-015 的下单后备注功能、当前文案或近期其他改动。
4. 若发现服务端原有字段不足，先记录具体差异，再评估最小必要调整；不得为本次视觉精简直接扩展后端或删除既有需求数据。

# FixPro 小程序备案、微信支付与云端部署攻略

> 适用范围：FixPro 客户小程序、师傅小程序、React 管理后台和 Go API。本文按“经营主体在中国大陆、API 部署在阿里云中国内地地域、使用阿里云 OSS、微信小程序内收款”给出路线。若服务器部署在中国香港/境外、经营主体不是企业/个体工商户，或使用微信支付服务商模式，办理入口和要求会不同；以对应平台后台及属地管局最终要求为准。
>
> 规则核对日期：2026-09-30。

## 先看结论：项目当前还不能直接生产上线

| 项目 | 当前代码状态 | 上线前要完成 |
| --- | --- | --- |
| 微信支付 | 尚无支付 API、支付单、支付回调实现；现有订单流程明确暂不包含支付 | 接入小程序下单、前端调起支付、支付通知验签/解密、查单、退款和对账 |
| 图片存储 | 图片本体写本地文件系统；数据库只存元数据和对象 Key | 实现并验证阿里云 OSS 存储适配器；当前 `APP_ENV=production` 禁止 local，而应用初始化又拒绝 s3，因此生产配置目前无法启动 |
| 客户端 API 域名 | `develop` 使用 localhost，`trial`/`release` 仍是 `example.com` 占位域名 | 换成已备案、HTTPS 可访问的测试/正式域名 |
| 师傅端 API 域名 | 目前固定为 `http://localhost:8080` | 改成按开发版/体验版/正式版环境切换的 HTTPS 域名 |
| 生产部署 | `deploy/compose.yaml` 是本地开发组合，含本地密码、HTTP 管理后台来源和本地媒体卷 | 单独准备生产环境配置、TLS 反向代理、密钥管理、数据库备份和对象存储 |

代码依据：支付范围说明见 [SPEC-004](specs/SPEC-004-订单履约与工单派单链路.md)；生产媒体驱动检查见 [app.go](../apps/server-go/internal/app/app.go) 和 [config.go](../apps/server-go/internal/platform/config/config.go)；小程序接口地址见客户端 [env.ts](../apps/wechat-mini/miniprogram/config/env.ts) 与师傅端 [env.ts](../apps/wechat-worker-mini/miniprogram/config/env.ts)；本地 Compose 见 [compose.yaml](../deploy/compose.yaml)。

## 一、先准备主体和账号资料

建议由实际负责经营、收款、开票和售后的主体统一办理。主体名称尽量保持一致：小程序主办主体、微信支付收款主体、用户协议/隐私政策主体、订单和售后责任主体。

准备以下信息，原件和电子扫描件都留存：

- 营业执照/主体证件、法定代表人或负责人证件、经办人及授权材料（按平台和属地要求）。
- 主体负责人、备案负责人、微信公众平台管理员、微信支付超级管理员的姓名、手机号、邮箱。
- 企业结算账户信息、经营类目及服务资质（若所选服务类目要求）。
- 客户小程序和师傅小程序各自的 AppID、管理员微信、名称、简介、服务类目、隐私政策和用户协议。
- 域名所有权、云服务器所属账号/地域、固定公网 IP、HTTPS 证书。
- 微信支付商户号 `mchid`、商户 API 证书私钥/序列号、APIv3 密钥；这些属于敏感凭证，不能提交到 Git 或小程序前端。

平台账号和 AppID 是两个小程序各自的身份。后端和 API 域名可以共用；哪个小程序内需要发起支付，哪个 AppID 就要与商户号完成绑定。客户端收款时，优先只给客户小程序配置支付能力；师傅端通常不需要支付能力。

## 二、按依赖顺序办理备案和域名

备案建议分成两条线看，不要把它们当成同一项：

1. **小程序/APP 备案**：为小程序本身办理主办者和应用信息备案。工信部通知明确将小程序等移动互联网应用纳入备案管理；在公众平台/小程序后台按当前流程申报。客户端和师傅端是两个 AppID，应分别检查其备案状态和所需材料。[工信部备案通知](https://www.gov.cn/zhengce/zhengceku/202308/content_6897341.htm?type=mobile-internet)
2. **API 域名 ICP 备案**：如果 API 域名解析到中国内地服务器并对外提供服务，域名需办理 ICP 备案。阿里云要求通过实际接入商的备案系统提交；阿里云内地服务器走阿里云 ICP 代备案系统。[阿里云 ICP 备案流程](https://help.aliyun.com/zh/icp-filing/basic-icp-service/user-guide/icp-filing-application-overview)

### 阿里云内地服务器的域名备案步骤

1. 购买并实名域名；确保域名后缀和注册商支持备案。域名实名认证完成后，留出信息同步时间。
2. 准备符合阿里云备案要求的中国内地服务器/轻量服务器和备案服务码。备案资格受实例地域、购买时长、账号和产品规格影响，提交前在阿里云备案控制台确认实例可选。[阿里云备案服务码 FAQ](https://help.aliyun.com/zh/icp-filing/basic-icp-service/support/server-check-faq)
3. 在阿里云 ICP 代备案系统录入主办单位、主体负责人、网站/App 信息和接入信息，上传材料并完成实人核验。
4. 等待阿里云初审和属地通信管理局审核；通过后按要求完成域名解析和接入。
5. 如 API 域名迁到其他云厂商，按实际接入商要求办理接入备案/变更，不要只改 DNS 就认为备案链路完成。

单位备案资料、负责人是否必须为法定代表人等要求因省份而异。先查主体注册地对应的[属地备案规则](https://help.aliyun.com/zh/icp-filing/basic-icp-service/support/fill-in-the-information-and-website-faq)，再约定负责人，减少退回重提。

如果 OSS 图片使用自定义域名或 CDN 域名，也把它纳入域名规划；阿里云说明 OSS 绑定自定义域名时，该域名需要有 ICP 备案。[阿里云备案接入信息说明](https://help.aliyun.com/zh/icp-filing/basic-icp-service/user-guide/icp-filing-server-access-information-check)

### 域名规划建议

先用一个主 API 域名，减少备案、证书和微信后台配置项：

| 用途 | 示例 | 配置位置 |
| --- | --- | --- |
| Go API | `api.example.cn` | 微信小程序 request 合法域名；Vite 管理后台 API 地址 |
| 图片/CDN（可后置） | `img.example.cn` | 小程序 download 域名；OSS/CDN 自定义域名 |
| 管理后台 | `admin.example.cn` | 管理员网页；不需要作为小程序 request 域名，除非小程序实际请求它 |

上线时在两个小程序后台分别配置实际用到的服务器域名：request、uploadFile、downloadFile；只有使用 WebSocket 才配置 socket 域名。均使用 HTTPS/WSS，不填端口。开发者工具里的“忽略合法域名校验”只用于本地开发，不能作为线上配置。[小程序网络域名说明](https://wdk-docs.github.io/wxadev-docs/framework/ability/network.html)

## 三、微信支付办理和项目接入

### 商户平台办理

1. 完成小程序注册和认证。微信支付文档说明，未认证的小程序账号不能申请小程序支付权限。
2. 申请微信支付商户号；支持的主体类型包括个体工商户、企业、事业单位、政府机关和社会组织，按商户平台要求提交经营和结算资料。
3. 在商户平台申请小程序支付权限，并将发起支付的客户小程序 AppID 绑定到商户号。若两个小程序都需要收款，逐个确认 AppID 绑定和相应权限。
4. 设定技术负责人/安全联系人，申请商户 API 证书并设置 APIv3 密钥；私钥只部署在后端密钥管理或受限文件中。
5. 确认小程序涉及的交易类运营要求和平台订单管理要求。微信支付文档特别提示，交易类小程序需按规范接入订单发货管理，否则可能影响正式支付权限。[小程序支付接入准备](https://pay.wechatpay.cn/doc/v3/merchant/4015459512)

微信支付前置准备、AppID 绑定和必要参数以商户平台为准：[小程序支付开发接入准备](https://pay.wechatpay.cn/doc/v3/merchant/4015459512) · [开发必要参数](https://pay.wechatpay.cn/doc/v3/merchant/4013070756)。

### FixPro 后端需要实现的支付闭环

不能只在小程序页面调用 `wx.requestPayment`。完整链路应该是：

1. 服务端根据当前订单和应收规则创建支付单，锁定金额、币种、支付用途和超时时间；金额由服务端计算，不能信任前端传值。
2. 服务端调用微信小程序下单接口，取得 `prepay_id`，生成小程序调起支付所需参数并返回给客户端。
3. 客户端调用 `wx.requestPayment` 拉起收银台。前端成功/失败回调只用于即时展示，不作为最终到账依据。
4. 微信支付向公网 HTTPS 回调地址发通知；后端验签、解密、校验商户号/AppID/金额/订单号，并在数据库事务中幂等更新支付单和订单账务状态。
5. 增加主动查单补偿、关单、退款、退款回调、日终对账和异常告警。

微信支付官方流程要求商户后端通过小程序下单获取 `prepay_id`，小程序调起支付；支付后要查单/核验支付结果并处理微信支付通知。[小程序支付开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791911) 当前 FixPro 订单状态与支付状态需要分开建模，不要把 `PENDING_CONFIRMATION` 直接当成“已支付”。建议增加独立支付单/支付状态，并支持定金、尾款、退款和重复回调幂等。

## 四、生产部署顺序

### 1. 先把生产基础设施搭好

- 准备生产域名、DNS、ICP 备案和 TLS 证书。
- 服务器仅对外开放 80/443 和受限管理入口；PostgreSQL 端口不要暴露公网，数据库只允许应用服务器/私网访问。
- API 放在反向代理之后；代理负责 HTTPS 终止并转发到 Go 服务内部端口。
- 准备 PostgreSQL 生产实例、自动备份、恢复演练、监控和告警。2 核 2G 可作为小规模 MVP 起步，但应控制连接池并观察内存、swap、磁盘和慢查询。
- 准备 OSS 私有 Bucket；商品公开图片可以经 CDN 访问，用户故障照片、师傅证件和工单证据保持私有，通过后端授权后返回短时签名 URL。

### 2. 完成项目生产化改造

- **OSS**：目前 `APP_ENV=production` 与媒体驱动配置互相卡住：配置层禁止生产使用 `local`，而 `app.New` 又拒绝 `s3`，所以现在没有可用的生产媒体驱动。接入真实 OSS SDK/适配层后，加入上传、读取、删除、私有访问签名、错误补偿和本地文件迁移；把 AccessKey 放在服务端环境密钥中，最好使用 RAM 最小权限角色。
- **支付**：现有项目未实现微信支付 API。新增配置项、密钥安全读取、下单、回调验签/解密、查单、关单、退款、支付记录和对账任务。
- **小程序环境地址**：客户端 `trial`/`release` 仍是占位域名；师傅端当前仍写死 localhost。改成开发/体验/正式配置，并确保开发工具上传的正式包指向生产域名。
- **服务端配置**：生产 `APP_ENV=production`，强制 TLS 数据库连接，设置正式 CORS、管理会话 Secure Cookie、强密码和禁用开发身份/Basic Auth；密钥不放在仓库。
- **管理后台**：构建静态资源并通过 HTTPS 域名发布，配置 API Base URL。当前 Vite 代理只适用于本地开发。
- **数据库迁移**：先备份，再在测试环境运行迁移；生产部署时使用独立迁移步骤，确认版本和回滚方案后再切流量。

`deploy/compose.yaml` 当前是本地开发配置，含 `fixpro-local` 等示例凭证、`MEDIA_DRIVER=local` 和开发 CORS，不要原样用于生产。

## 五、上线前验收清单

### 主体和微信平台

- [ ] 客户小程序、师傅小程序的 AppID、主体、管理员和类目确认。
- [ ] 两个小程序分别完成平台要求的备案并能查询备案状态。
- [ ] 运营类目与实际家庭维修/上门服务相符，所需资质和隐私政策齐全。
- [ ] 客户支付 AppID 与商户号绑定，商户结算账户和安全联系人已配置。
- [ ] 提交体验版审核时准备可用测试账号、测试订单和审核路径。

### 域名、服务器和 OSS

- [ ] API 域名解析正确，ICP 备案和 TLS 证书有效。
- [ ] 两个小程序后台的 request/upload/download 域名配置正确；真机网络请求成功。
- [ ] 管理后台 HTTPS 可登录，API Cookie/跨域配置正确。
- [ ] PostgreSQL 不对公网开放，自动备份已启用并完成至少一次恢复验证。
- [ ] OSS 上传、下载、私有访问鉴权、过期链接、删除和旧本地文件迁移已验收。

### 支付和业务

- [ ] 正常支付、用户取消、重复点击、超时支付、重复/延迟回调、查单补偿均通过。
- [ ] 支付金额始终由后端订单数据确定；前端不能直接改金额。
- [ ] 支付成功才更新支付状态；支付成功但用户端超时返回时，重新进订单仍显示正确状态。
- [ ] 定金、尾款、退款、退款失败和账单对账流程有明确规则。
- [ ] 客户端、管理后台、师傅端对支付与履约状态展示一致。

## 六、建议的办理节奏

1. **主体/账号**：确认公司或个体工商户主体、两个小程序 AppID、商户号现状和实际服务类目。
2. **域名/备案**：域名实名认证 → 阿里云备案资格确认 → ICP 备案和小程序备案并行办理 → DNS/TLS。
3. **技术底座**：生产 PostgreSQL、Go/API、管理后台、日志备份先部署到测试域名；小程序真机请求跑通。
4. **图片链路**：接入 OSS 并迁移/验证图片，确认私密证据不会被公开访问。
5. **支付闭环**：开通商户号和 AppID 绑定后实现后端支付单、回调、查单、退款。
6. **提审发布**：使用正式域名和真实类目提交两个小程序；根据审核意见修正后发布，逐笔核对账单。
